# 가상 AI 회사 요구사항

현재 대화에서 도출한 요구사항 초안이다. **핵심**은 사용자가 요청한 방향, **제안**은 구체화를 위한 설계안, **확장**은 이후 범위다. 모든 항목은 아직 구현 전이며, 미확정 사항은 마지막 절에 모았다.

## 1. 목표와 사용 시나리오

사용자는 Commander로서 여러 공급자의 에이전트를 가상 회사의 직원처럼 등록하고, 업무를 지시하며, Q&A와 결과 판단을 수행한다. 출근·퇴근 시 각 PC에서 동일한 Docker 구성을 실행하고, 이전 작업을 중지한 뒤 GitHub 기반 인계로 이어간다.

운영 원칙은 [rules.md](rules.md)를 따른다. 화면 구성은 대화에서 합의한 공간·직원·업무 표현을 바탕으로 구체화한다.

## 2. 기능 요구사항

| ID | 구분 | 요구사항 |
| --- | --- | --- |
| FR-01 | 핵심 | Docker 환경을 실행하고 로컬 브라우저에서 사무실 GUI에 접속할 수 있다. |
| FR-02 | 핵심 | OpenAI, Claude, Meta Muse, Google Gemini 연동을 준비한다. 공급자별 연결 방식은 검증 후 확정한다. |
| FR-03 | 핵심 | 채용 흐름으로 직원을 등록하고 새 에이전트 세션을 실행할 수 있다. |
| FR-04 | 핵심 | 지원되는 기존 로컬 세션을 발견하고 회사에 연결할 수 있다. 임의의 모든 프로세스·웹 대화 자동 제어는 보장하지 않는다. |
| FR-05 | 핵심 | 직원별 모델과 지원되는 추론 강도를 설정할 수 있다. |
| FR-06 | 핵심 | Commander가 업무를 지시하고, 직원과 질문·답변을 주고받으며, 결과를 확인할 수 있다. |
| FR-07 | 제안 | 직원 상세 화면에 역할, 실행 위치, 연결 상태, 세션, 현재 업무, 설정과 결과물을 표시한다. |
| FR-08 | 제안 | 관찰·재개·실시간 제어·중단·설정 변경 지원 여부를 직원별로 표시한다. |
| FR-09 | 제안 | 업무 대기, 실행 중, 답변 또는 승인 대기, 완료, 실패, 중단, 연결 끊김을 구분한다. |
| FR-10 | 핵심 | PC 이동 전 작업을 중지하고, 다음 PC에서 업무를 이어갈 수 있는 인계 내용을 남긴다. |
| FR-11 | 제안 | 재시작 후 직원 정보와 저장된 업무 상태를 복원하고, 미완료 작업은 재개 대기로 표시한다. |
| FR-12 | 제안 | 직원 간 질문·검토 요청을 지원한다. 자동 협업과 대화 종료 조건은 추가 정의한다. |
| FR-13 | 확장 | 지속 업무를 위해 동일한 기본 구성을 클라우드에서 상시 실행할 수 있다. |
| FR-14 | 핵심 | 사용자가 개발 중인 wShell, wPost, wText를 소개하는 간단한 프로그램 배너를 표시한다. 각 배너는 프로그램명, 한 줄 소개, GitHub 저장소 링크를 포함한다. |

## 3. 연결 방식과 한계

| 대상 | 우선 검토할 연결 방식 | 검증할 사항 |
| --- | --- | --- |
| OpenAI | Codex App Server 또는 API 기반 실행 | 사용 대상이 Codex인지, 접근 가능한 스레드와 재개 범위 |
| Claude | Claude Code CLI 또는 Agent SDK | 인증, 세션 재개, 실행 중 세션 연결 범위 |
| Google Gemini | Gemini CLI 또는 API 기반 실행 | 세션 저장·재개와 프로그램 제어 범위 |
| Meta Muse | Meta Model API 기반 실행 | 모델 기반 신규 직원과 Muse 앱 기존 세션의 구분, 계정 접근 가능 범위 |

공식 문서상 세션 재개 기능이 있더라도 타 앱에서 실행 중인 세션의 실시간 제어까지 보장하지 않는다. Meta 모델 기반 실행과 소비자용 Muse 앱 세션 연결도 별도 기능으로 검증한다.

## 4. 화면 구성 제안

- 중앙 사무실: 직원 캐릭터와 업무 상태. 캐릭터 선택 시 상세 화면을 연다.
- 좌측 공간 탐색: 부서·프로젝트 또는 층 선택. 실제 공간 구성은 미확정이다.
- 우측 Commander 패널: 답변·판단 대기, 막힌 업무, 완료 결과, 활동 기록.
- 직원 상세: 대화, 현재 업무, 모델 설정, 실행 기록, 결과물.
- 채용 화면: 이름, 역할, 공급자, 실행 방식, 모델, 지원 설정, 작업 위치.
- 인계 화면: 중지할 업무, 저장 결과, 관련 커밋, 다음 PC에서 재개할 내용.

고정된 등각투영 배경에 캐릭터와 클릭 영역을 배치하는 2.5D 방식을 후보로 둔다. 자유 이동형 3D와 Electron 앱은 초기 필수 요구사항이 아니다.

### 4.1. 프로그램 소개 배너

세 저장소의 README를 바탕으로 아래 문구를 사용한다. 간단한 카드형 배너로 구성하며, 정확한 배치 위치와 색상은 UI 설계 단계에서 정한다.

> **wShell · 서버 접속과 파일 전송을 한곳에서**
>
> 여러 서버의 SSH 접속과 SFTP 파일 전송을 한 창에서 관리하는 네이티브 터미널.
>
> [GitHub에서 보기](https://github.com/parkhw328/wook-shell)

> **wPost · API 요청과 응답을 간편하게**
>
> API 요청을 보내고 응답을 확인하며, 자주 쓰는 요청을 컬렉션으로 관리하는 Windows용 한국어 데스크톱 앱.
>
> [GitHub에서 보기](https://github.com/parkhw328/wook-post)

> **wText · 문서 편집과 차이 비교를 한곳에서**
>
> 여러 문서의 탭 편집, 작업 폴더 탐색, 두 파일이나 텍스트의 차이 비교를 지원하는 Windows용 무료 텍스트 편집기.
>
> [GitHub에서 보기](https://github.com/parkhw328/wook-text)

- 프로그램 이름은 각 README의 표기인 wShell, wPost, wText를 따른다.
- 배너 링크는 해당 GitHub 저장소로 이동하며, 소개 문구와 링크를 키보드와 작은 화면에서도 확인할 수 있도록 구성한다.
- 이번 범위는 프로그램 소개와 링크 제공이다. 프로그램 실행, 설치 여부 감지, 에이전트와의 기능 연동은 별도 요구사항으로 정의한다.
- 버전 번호와 다운로드 파일 주소는 배너에 고정하지 않는다.

문구 확인 출처: [wShell README](https://github.com/parkhw328/wook-shell/blob/main/README.md), [wPost README](https://github.com/parkhw328/wook-post/blob/main/README.md), [wText README](https://github.com/parkhw328/wook-text/blob/main/README.md).

## 5. PC 이동 흐름

1. 현재 PC에서 신규 업무 접수를 중단한다.
2. 진행 업무를 정리하거나 중단하고 미완료 상태를 기록한다.
3. 목표, 완료 내용, 남은 작업, 파일 변경과 다음 행동을 인계 기록에 저장한다.
4. 공유 가능한 코드와 인계 자료를 GitHub에 반영한다. 개발 작업은 rules.md의 중간 커밋·푸시 원칙을 따르며, 제품 내 인계 자동화 방식은 별도로 정한다.
5. 다른 PC에서 변경 내용을 가져오고 Docker 환경을 실행한다.
6. 인증과 작업 폴더를 확인한 후, 가능한 세션은 재개하고 나머지는 인계 기록으로 새 세션을 시작한다.

컨테이너 프로세스 자체의 이동이나 공급자 내부 기억의 완전 복원은 요구하지 않는다. 동일 업무의 양쪽 PC 동시 실행은 초기 운영 범위에서 제외한다.

## 6. 초기 검증 기준 제안

- 문서화한 실행 절차로 GUI가 열리고, 인증 미설정 상태가 명확히 표시된다.
- 지원되는 공급자 연결에서 신규 직원 생성, 업무 지시, Q&A, 결과 확인이 가능하다.
- 기존 세션은 실제 지원 수준대로 연결되고, 미지원 제어는 사용할 수 없다.
- 정상 종료·재시작 후 직원과 업무 기록이 유지되며, 중단 작업이 완료로 오인되지 않는다.
- 두 PC 사이의 인계에서 다음 행동과 파일 변경을 확인할 수 있고, 원래 세션 재개와 새 세션 시작을 구분한다.
- 컨테이너 이미지·저장소·인계 자료와 로그에 개인정보, 비밀번호, API 키, 로그인 토큰 등 중요 정보가 포함되지 않는다.
- 개발 중 주고받은 로컬 참고 자료는 제품 화면·공개 문서·배포 산출물에 포함되지 않는다.
- 연결 끊김과 공급자 오류가 GUI에 반영되며, 복구 과정에서 업무를 자동 중복 실행하지 않는다.
- 프로그램 배너 세 개에 정확한 이름·소개·저장소 링크가 표시되고, 각 링크가 해당 프로그램의 GitHub 저장소로 연결된다.

## 7. 후속 작성 항목

- [ ] 공급자별 실제 사용 제품, 계정·API 인증, 연동 우선순위
- [ ] MVP에서 반드시 지원할 기존 세션의 종류와 연결 수준
- [ ] 기술 스택, 이미지 구성, 영속 볼륨과 DB 설계
- [ ] 직원 정의·업무·인계 기록의 데이터 형식과 저장 경로
- [ ] 제품 내 GitHub 인계 범위와 자동화 방식 (개발 중 커밋·푸시 원칙은 확정)
- [ ] Commander 승인 대상과 에이전트 자율 실행 범위
- [ ] 에이전트 간 대화·업무 위임·공유 기억 규칙
- [ ] 작업 폴더 접근 권한, 동시 파일 수정 방지 방식
- [ ] 비용·시간·대화 횟수 제한과 사용량 표시 범위
- [ ] 공간 디자인, 캐릭터와 그래픽 자산 정책
- [ ] 비정상 종료·백업·복구와 클라우드 원격 접속 정책
