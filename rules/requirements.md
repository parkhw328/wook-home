# 가상 AI 회사 요구사항

현재 대화에서 도출한 요구사항이다. **핵심**은 사용자가 요청한 방향, **제안**은 구체화를 위한 설계안, **확장**은 이후 범위다. 전체 목표가 모두 구현된 것은 아니며, 현재 구현 범위는 아래 표에서 구분한다.

## 1. 목표와 사용 시나리오

사용자는 Commander로서 여러 공급자의 에이전트를 가상 회사의 직원처럼 등록하고, 업무를 지시하며, Q&A와 결과 판단을 수행한다. 출근·퇴근 시 각 PC에서 동일한 Docker 구성을 실행하고, 이전 작업을 중지한 뒤 GitHub 기반 인계로 이어간다.

운영 원칙은 [rules.md](rules.md)를 따른다. 화면 구성은 대화에서 합의한 공간·직원·업무 표현을 바탕으로 구체화한다.

| FR-16 | 핵심 | 메인 사무실은 선택한 테마에 맞는 배경·조명, 목재 바닥, 청색 창과 따뜻한 조명의 입체 실내로 구성한다. 다크 테마는 어두운 네이비 배경을 사용한다. 주요 작업의 레드 계열 강조색, 실제 상태에 연결되는 캐릭터 동작 및 동작 줄이기를 유지한다. |

| FR-18 | 핵심 | StackQueue Blog 소개 배너에 네이버 블로그 링크를 제공한다. |
| FR-19 | 핵심 | 벽·문·복도가 있는 실제 사무실 구조로 메인화면을 구성하고, 사무실·회의실·대표이사실·휴게실·다과실을 독립된 방으로 표현한다. 이름·상태·버튼·메뉴와 긴 본문은 작은 화면에서도 읽고 조작할 수 있어야 한다. |
| FR-20 | 핵심 | 지원되는 로컬 Codex 세션에 실제 지시를 전송하고 접수 상태를 확인한다. 연결이 필요한 경우 Wiki에 실행·직접 연결·문제 해결 절차를 제공한다. |
| FR-21 | 핵심 | 연동 준비 중인 공급자에 공식 서비스 열기와 연결 안내를 제공한다. 외부 서비스 로그인만으로 사무실 연동이 완료된 것처럼 표시하지 않는다. |
| FR-22 | 핵심 | Commander가 복도를 따라 문을 거쳐 입장·퇴실할 수 있다. 현재 위치, 목적지, 이동 상태를 표시하고 방 선택 버튼·키보드·동작 줄이기를 지원한다. 벽을 가로지르는 이동은 허용하지 않는다. |
| FR-23 | 핵심 | 방에 입장하면 그 공간의 직원·세션·업무를 선택한다. 사무실에서 지시와 진행 내용을 보고, 회의실에서 직원·세션의 협업을 확인하며, 대표이사실에서 Commander 질문에 답하고 업무보고·결과를 검토·승인한다. 방 이동 자체는 실행 상태를 변경하지 않는다. |
| FR-24 | 핵심 | 선택한 CLI 세션의 최근 사용자 지시·에이전트 응답을 터미널 형태의 대화기록으로 보여 준다. 세션 식별, 역할·시각, 검색·역할 필터, 최신 기록 이동, 수집 범위와 잘림 안내를 제공한다. |
| FR-25 | 핵심 | CLI 기록은 선택한 작업 공간에 한정해 명시적으로 활성화한다. 시스템 지침·내부 추론·도구 원문을 제외하고 알려진 비밀 정보와 개인 경로를 마스킹한다. 연결 끊김·기록 없음·미설정과 체험 대화를 구분하며 인계·Git·배포물로 내보내지 않는다. |
| FR-26 | 핵심 | 자동 갱신 중 선택한 방·세션·검색·작성 중인 지시·읽던 스크롤을 보존한다. 많은 직원과 세션은 목록에서 빠짐없이 접근할 수 있고 작은 화면에서도 모든 방과 업무 기능을 사용할 수 있다. |
| FR-27 | 핵심 | 지원 CLI의 새 실행과 종료를 약 5초 주기의 호스트 프로세스 관찰로 반영한다. 첫 메시지 전에도 표시하고 PID·시작 시각으로 재실행을 구분한다. 같은 PC의 감지 범위, 실행 중·종료·확인 필요·감지 미지원·연결 끊김과 최근 종료 시각을 표시하며 저장 대화 UUID에 임의 연결하지 않는다. |
| FR-28 | 핵심 | 지원되는 CLI와 AI 웹 탭을 함께 감지하는 도구와 통합 목록을 제공한다. Windows와 Linux의 Codex·Claude Code·Gemini CLI 및 Chrome/Chromium의 ChatGPT·Claude·Meta AI·Gemini를 지원하며, 공급자·CLI/웹 구분·감지 범위·갱신 시각·지원 기능을 표시한다. Linux는 호스트의 같은 유효 UID, Windows는 같은 로그인 세션으로 한정한다. 설치·실행 감지는 해당 공급자의 지시 전송 지원과 구분한다. |
| FR-29 | 핵심 | 여러 창·같은 공급자의 여러 대화를 동시에 표시한다. 같은 대화의 중복 탭은 한 대화와 탭 수로 집계하고 새 대화·서비스 화면은 대화 세션과 별도로 표시한다. 탭 닫기·다른 사이트로 이동·감지 연결 끊김을 실제 상태에 맞게 반영한다. |
| FR-30 | 핵심 | 웹 탭 감지는 명시적으로 연결한 브라우저 프로필과 허용된 AI 도메인으로 한정한다. 대화 제목·본문·쿠키·인증 정보·전체 URL을 전달하지 않으며 감지 정보는 로컬 메모리에만 보관하고 인계·Git·배포물에서 제외한다. |

## 4. 메인화면과 공간별 업무 — 확정

메인화면의 중심은 여러 층의 높이와 깊이가 드러나는 입체 사무실이다. 각 층의 방과 복도, 벽, 출입문, 공간별 가구로 용도를 알아볼 수 있어야 한다. 층·방 선택 → 복도·층간 연결 이동 → 문을 통한 입장 → 직원·세션·업무 선택 → 대화·업무보고 → 퇴실 흐름을 제공한다. 현재 층·위치와 입장한 방의 작업 패널을 함께 보여 주며, 텍스트 레이블은 축소하거나 원근 변환하지 않는다.

층 배치의 구현안은 1층 로비·휴게실·다과실, 2층 업무 사무실·유리 회의실, 3층 대표이사실·발표 공간이다. 기본 시점은 2층 내부다. 사무실과 회의실을 같은 층에서 이어 직원의 협업 동선을 보여 주고, 대표이사실 질문·발표는 엘리베이터로 연결한다. 층 구성은 공간 탐색과 가독성을 기준으로 조정할 수 있으며 다섯 필수 공간의 업무 흐름은 유지한다.

가로로 이어지는 방과 복도를 중심으로 건물 폭을 넓히고 장면을 본문 전체 폭에 배치한다. 전체 보기는 여러 층의 관계를 보여 주며, 층 선택 시 해당 층만 독립적으로 펼쳐 책상 사이 통로·유리벽·엘리베이터와 방의 깊이가 보이는 사선 시점을 제공한다. 책상 열 사이와 출입문으로 이어지는 통로를 확보하고 직원은 가구를 가로지르지 않는다. 전체화면과 일반 화면의 카메라는 화면 비율에 맞춰 건물을 담으며 확대는 인물·가구에만 적용하고 이름표의 글자 크기를 유지한다. 평상시 복도 안내와 현재 이동 경로는 시각적으로 구분하고, 전체화면에서도 방 선택·업무 패널·종료 조작을 사용할 수 있어야 한다.

| 공간 | 구성과 동작 |
| --- | --- |
| 복도 | 각 방의 문을 연결하는 이동 동선, 현재 위치와 목적지 안내 |
| 사무실 | 직원 책상과 CLI 세션, 업무 지시·진행 확인·대화기록 |
| 회의실 | 회의 테이블, 협업한 직원·세션의 참여 상태와 관련 대화, 논의 동작 |
| 대표이사실 | 대표 책상과 발표 화면, Commander 질문·답변, 업무보고·결과 검토·승인 |
| 휴게실 | 소파와 휴식 좌석, 대기 중인 직원 확인. 실제 실행 중지 기능으로 해석하지 않음 |
| 다과실 | 커피·간식·공용 테이블, 사무실 소식과 휴식 공간. 실제 실행 상태와 분리 |

입장한 공간의 업무 패널에는 선택 대상과 상태를 명확히 표시한다. CLI 대화기록은 원문을 HTML로 실행하지 않고 읽기 전용 텍스트로 표시한다. 실제 지시 전송과 접수 상태는 기록 열람과 분리하며 큐 접수를 업무 완료로 표시하지 않는다. 기록 연결이 꺼져 있으면 활성화 방법, 기록이 없으면 빈 상태, 갱신이 멈추면 마지막 수신 상태임을 안내한다.

채용·공급자 연결 관리·업무 보드·인계와 프로그램·블로그 배너는 유지한다. 다층 입체 표현은 필수이며 자유 카메라 이동과 Electron 앱은 초기 필수 요구사항이 아니다.

### 4.3. 한글·영문·숫자 공통 글자 가독성 — 확정

한글·영문·숫자 모두 아래 크기 기준을 지킨다. 이 기준은 기존 화면과 이후 추가하는 화면, 사이드바, 대화상자, 방·직원 레이블, 대화 터미널, 연결 점검과 하단 정보에 공통 적용한다. 같은 역할의 한글과 영문은 같은 크기를 사용한다.

브라우저 기본 글꼴이 16px이고 확대율이 100%일 때의 기준은 다음과 같다. `html`의 글꼴 크기는 `100%`로 두고 공통 크기 토큰을 `rem`으로 정의하여 사용자 글꼴·확대 설정을 존중한다.

| 용도 | 기본 크기 | 공통 토큰 | 적용 예 |
| --- | --- | --- | --- |
| 보조 레이블·상태·시각·버전 | **최소 14px / .875rem** | `--font-caption` | 로컬 서버 연결 상태, WORKSPACE, 영문 소제목, 상태 배지, 확인 시각, 버전 |
| 안내·카드 보조 본문 | 15px / .9375rem | `--font-small` | 연결 안내, 카드 설명, 도움말 링크 |
| 버튼·입력·선택·목록 이름 | 16px / 1rem | `--font-control` | 공급자·모델 선택, 직원 이름, 탐색·작업 버튼 |
| 일반 본문·대화 | 17px / 1.0625rem | `--font-body` | 페이지 설명, 업무 본문, CLI 대화 |
| 강조 문구 | 18px / 1.125rem | `--font-emphasis` | 프로그램 이름, 주요 안내 |
| 구역 제목 | 22px / 1.375rem | `--font-heading` | 사무실·대화·감지 영역 제목 |

- **14px 미만의 읽기용 글씨를 새로 추가하거나 다시 적용하지 않는다.** 모바일 전용 CSS, 뒤에 로드되는 스타일, `small` 기본 스타일도 같은 기준을 지킨다. 화면 공간이 부족하면 열을 줄이거나 문구를 자연스럽게 줄바꿈하고 여백을 조정한다.
- CLI 대화의 검색 입력과 역할 선택은 같은 높이(기본 44px)를 사용하고, 한 행에서는 라벨 유무와 관계없이 입력 상자의 위·아래 테두리를 맞춘다. 모바일에서 세로로 배치되어도 같은 높이와 글자 크기를 유지한다.
- 영문 대문자 소제목의 자간은 `0`~`.06em`, 줄 높이는 최소 `1.6`으로 한다. 안내·대화 본문은 줄 높이 `1.75`~`1.85`를 기본으로 하며, 글씨를 연한 색·낮은 투명도로 바꿔 식별하기 어렵게 만들지 않는다.
- 읽어야 하는 이름·상태·숫자를 `scale`·`zoom`·원근 변환으로 축소하지 않는다. 공간·캐릭터를 축소하더라도 텍스트 레이블의 화면상 크기는 유지한다.
- 공통 가독성 스타일을 화면별 스타일 뒤에 적용한다. 이후 새 화면과 새 미디어 쿼리도 이 토큰을 사용하며, 예외가 필요하면 구현 전에 요구사항의 변경 근거를 명시한다.
- 완료 전 브라우저에서 **최종 계산된 글꼴 크기**를 확인한다. 사무실 이름·로컬 서버 연결 상태, `WORKSPACE`, 페이지·대화상자 영문 소제목, 공급자·모델명, `CONVERSATION`, `Commander`, 시각·버전을 포함한다.
- 320px·390px·768px·1366px·1920px에서 글자 크기 유지와 가로 넘침·겹침·잘림을 검증한다. 200% 브라우저 확대에서도 조작과 읽기가 유지되도록 한다. 코드에 크기만 선언한 것은 완료 근거가 아니다.

### 4.4. 버튼의 역할과 상태 — 확정

- 버튼·선택 카드·대화상자·알림·장면 이름표를 그림자 없는 평면형으로 표시한다. 기본·포인터 올림·누름·선택·비활성 상태에 하단 그림자나 안쪽 음영을 추가하지 않는다. 누름은 배경색·테두리색으로, 선택은 테두리·굵은 글씨로, 키보드 초점은 파란 외곽선으로 구분한다. 두 테마와 모든 화면·대화상자·전체화면에서 최종 계산 스타일을 검증한다. 입체 사무실과 캐릭터의 그림 표현은 별도다.
- 주요 실행·전송·저장·승인은 진한 레드 배경과 흰 글씨, 700 굵기로 표시한다. 같은 작업 묶음 안에서는 다음 행동 하나에 우선순위를 주며 이동·닫기·새로고침·다운로드는 중립색 테두리의 600 굵기 보조 버튼을 사용한다. 도움말·모두 보기는 밑줄 링크와 500 굵기로 구분한다.
- 일시중지·연결 해제는 황토색 계열의 주의 버튼, 업무 취소는 빨간 글씨·테두리의 취소 버튼으로 구분한다. 동작을 구체적으로 적고, 일시중지 버튼이 재개로 바뀌면 주요 실행 스타일도 함께 전환한다. 단순 창 닫기·양식 취소에 위험 강조를 적용하지 않는다.
- 선택한 층·방·탭과 켜진 토글은 배경색 외에 굵은 글씨와 선 표시를 함께 사용한다. `aria-pressed`, `aria-selected`, 현재 페이지 상태와 시각 표현을 일치시키며 토글 해제 시 기본 표현으로 돌아간다.
- 포인터 올림·누름·키보드 초점·비활성 상태를 공통으로 구분한다. 키보드 초점은 선택 상태와 다른 외곽선으로 표시한다. 비활성 버튼은 주요 실행색과 투명도를 사용하지 않고 읽을 수 있는 회색으로 표시하며 기존 불가 사유 안내를 유지한다.
- 아이콘 버튼·장면 조절·직원 이름 버튼까지 최소 44px 높이, 일반 버튼 글씨 최소 16px를 유지한다. 긴 버튼은 글씨 축소 대신 자연스럽게 줄바꿈하며 대화상자·작은 화면에서 잘리거나 겹치지 않는다. 같은 줄의 장면 확대·맞춤 버튼도 높이를 맞춘다.
- 색상은 공통 행동 토큰으로 관리하여 밝은 화면과 어두운 화면에 적용할 수 있게 한다. 실제 브라우저에서 주요/보조/주의/취소/선택/비활성 상태의 글씨 대비, 키보드 조작, 320px~1920px 배치와 전환 결과를 검증한다.

## 5. PC 이동 흐름

1. 현재 PC에서 신규 업무 접수를 중단한다.
2. 진행 업무를 정리하거나 중단하고 미완료 상태를 기록한다.
3. 목표, 완료 내용, 남은 작업, 파일 변경과 다음 행동을 인계 기록에 저장한다.
4. 공유 가능한 코드와 인계 자료를 GitHub에 반영한다. 개발 작업은 rules.md의 중간 커밋·푸시 원칙을 따르며, 제품 내 인계 자동화 방식은 별도로 정한다.
5. 다른 PC에서 변경 내용을 가져오고 Docker 환경을 실행한다.
6. 인증과 작업 폴더를 확인한 후, 가능한 세션은 재개하고 나머지는 인계 기록으로 새 세션을 시작한다.

컨테이너 프로세스 자체의 이동이나 공급자 내부 기억의 완전 복원은 요구하지 않는다. 동일 업무의 양쪽 PC 동시 실행은 초기 운영 범위에서 제외한다.

## 6. 초기 검증 기준 제안

- 문서화한 실행 절차로 GUI가 열리고, 인증 미설정 상태가 명확히 표시된다.
- 지원되는 공급자 연결에서 신규 직원 생성, 업무 지시, Q&A, 결과 확인이 가능하다.
- 기존 세션은 실제 지원 수준대로 연결되고, 미지원 제어는 사용할 수 없다.
- 정상 종료·재시작 후 직원과 업무 기록이 유지되며, 중단 작업이 완료로 오인되지 않는다.
- 두 PC 사이의 인계에서 다음 행동과 파일 변경을 확인할 수 있고, 원래 세션 재개와 새 세션 시작을 구분한다.
- 컨테이너 이미지·저장소·인계 자료와 로그에 개인정보, 비밀번호, API 키, 로그인 토큰 등 중요 정보가 포함되지 않는다.
- 개발 중 주고받은 로컬 참고 자료는 제품 화면·공개 문서·배포 산출물에 포함되지 않는다.
- 연결 끊김과 공급자 오류가 GUI에 반영되며, 복구 과정에서 업무를 자동 중복 실행하지 않는다.
- 프로그램 배너 세 개에 실제 앱 아이콘과 정확한 이름·소개·저장소 링크가 표시되고, 각 링크가 해당 프로그램의 GitHub 저장소로 연결된다. 데스크톱과 320px 화면에서 아이콘 로드·비율·잘림·이름 가독성을 확인한다.
- 블로그 배너는 지정한 네이버 블로그로 연결되고, 사무실 이름 설정은 화면과 인계 데이터에 일관되게 적용된다.
- 실제 Codex 세션 관찰은 데이터 갱신 중단과 오래된 활동을 구분한다. 관찰 세션을 체험 업무의 완료 집계에 포함하거나 사무실 중지로 CLI가 중단된 것처럼 표시하지 않는다.
- CLI 첫 메시지 전 실행 추가, 정상 종료, 비정상 종료, PID 재사용, 오래 대기하는 프로세스, 감지 실패·복구, 연결 프로그램 중단을 검증한다. 조회 실패나 기록 정지로 종료를 만들지 않으며 실행 인수·대화·인증·개인 경로를 프로세스 감지 결과에 노출하지 않는다.
- 다섯 방의 독립된 벽·문과 연결 복도가 식별되며, 서로 다른 방 사이를 이동할 때 문과 복도를 거친다. 입장·퇴실·현재 위치와 동작 줄이기를 검증한다.
- 여러 층의 높이·앞뒤 깊이와 층별 방을 구분하고 전체 층·층별 보기를 확인한다. 다른 층의 방 사이 이동과 직원 보행이 문·복도·층간 연결 경로를 따르는지 검증한다.
- 사무실에서 업무 지시, 회의실에서 세션 간 협업, 대표이사실에서 질문 답변·발표·결과 승인이 이어진다. 실패·중단·미연결을 완료로 집계하지 않는다. 구조화 활동의 시작·응답·중단·유효기간 종료·연결 끊김과 동작 줄이기를 검증한다.
- CLI 기록의 선택한 프로젝트·세션 분리, 역할과 시각, 최근 기록 한도, 비밀 마스킹, 시스템·추론·도구 제외, HTML 비실행을 검증한다. 미설정·빈 기록·연결 끊김도 확인한다.
- 320px·390px·태블릿·데스크톱에서 모든 방과 대화·보고 기능에 접근하며, 자동 갱신이 선택·검색·작성·스크롤을 초기화하지 않는다.
- CLI와 네 AI 웹사이트의 동시 감지, 같은 공급자의 복수 대화, 중복 탭, 새 대화 화면, 허용 도메인 밖 이동, 탭 닫기, 연결 중단·복구와 빈 결과를 검증한다. 감지 데이터에 제목·본문·인증 정보·전체 URL이 없고 인계에 포함되지 않는지 확인한다.
- 통합 점검에서 API 미설정과 잘못된 인증, 정상 모델 목록, 요청 제한, 시간 초과, 잘못된 응답, 오래된 결과와 복구를 검증한다. 동시에 점검해도 외부 요청이 중복되지 않고 리디렉션·임의 주소로 인증 정보가 전달되지 않아야 한다. 실제 키가 없는 공급자는 실계정 인증 미검증으로 기록한다.

- 검색은 오래된 CLI·다른 프로젝트 분리, 웹 개별 동의·탭 닫힘·재시작 보관, 한글·특수문자·역할 필터·페이지 전환, 지연 응답, HTML 비실행, 비밀 마스킹과 인계 제외를 검증한다. CLI 모달은 세션 클릭 즉시 열림·닫기·초점 복귀·읽던 위치와 필터 보존·최신 이동을 실제 브라우저에서 확인한다.
