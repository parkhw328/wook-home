# 버전 및 릴리스 관리

현재는 미출시 상태다. 첫 실행 가능한 검증 버전부터 0.x.y를 사용하고, 안정화 시 1.0.0으로 전환한다.

## 버전 선택

| 규모 | 기준 | 안정 버전 예시 |
| --- | --- | --- |
| 대 · MAJOR | 사용법·설정·데이터의 호환성을 깨는 변경 | 1.2.3 → 2.0.0 |
| 중 · MINOR | 호환성을 유지하는 새 기능 | 1.2.3 → 1.3.0 |
| 소 · PATCH | 호환성을 유지하는 수정·작은 개선 | 1.2.3 → 1.2.4 |

0.x 개발 기간에는 호환성 파괴 변경 시 MINOR를 올리고 이전 방법을 명시한다. 문서 변경은 Unreleased에 모을 수 있으며 매 커밋마다 버전을 올리지 않는다.

## 릴리스 순서

1. 출시 범위를 정하고 관련 테스트·빌드·실행 검증을 수행한다.
2. 사용설명서와 README를 실제 제공 기능에 맞게 갱신한다.
3. CHANGELOG.md의 해당 Unreleased 내용을 버전과 날짜(YYYY-MM-DD) 아래로 옮긴다.
4. 프로젝트에 버전 필드가 도입되면 코드·패키지·배포물 버전을 일치시킨다.
5. 변경을 커밋·푸시하고 검증한 커밋에 vMAJOR.MINOR.PATCH 태그를 생성·푸시한다.
6. 해당 태그의 GitHub Release에 아래 내용을 작성하고 검증된 배포물만 첨부한다. 시험 배포는 prerelease로 표시한다.
7. 게시 결과, 태그와 다운로드 링크를 확인하고 새 Unreleased 항목을 유지한다.

게시한 버전과 태그는 덮어쓰지 않는다. 문제 수정은 새 버전으로 배포한다. 현재는 앱과 빌드가 없어 태그·Release를 생성하지 않는다.

```markdown
# vX.Y.Z · 릴리스 제목

## 주요 변경
- 추가:
- 변경:
- 수정:

## 호환성과 업데이트
- 호환성 변경 및 필요한 이전 작업:
- 설치·업데이트 방법:

## 검증
- 검증 환경과 수행한 테스트:
- 배포물과 확인 결과:

## 알려진 제한
- 미지원 기능 또는 남은 문제:

## 문서
- 해당 버전의 사용설명서와 변경 이력 링크:
```
