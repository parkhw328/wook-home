# 0.2.2 탐색 정렬·패널 배치 검증

2026-10-28에 FR-77을 기준으로 확인했다. 브라우저 업무 검증에는 별도 합성 계정과 기록을 사용했으며 실제 AI 호출·지시 전송을 수행하지 않았다.

## 변경과 검증

- wPost·wText 설명을 한 줄로 줄이고 기존 글자 크기를 유지했다. 움직임 버튼은 맵 상단 오른쪽에 다른 조작과 간격을 두었다.
- 하단 층·방 버튼은 여유 폭 안에서 가운데 정렬한다. 넘치는 경우 첫 항목부터 가로 스크롤·방향키·Home·End로 접근한다.
- 넓은 화면에서는 맵과 오른쪽 방 설명 패널이 함께 늘어나 위아래가 맞는다. 1250px 이하는 각 내용 높이대로 쌓인다.
- Commander의 데스크와 사무실 소식을 맵·업무보고 아래의 독립 구역으로 옮겼다. 직원 관리 메뉴를 접어도 업무 열기·업무 보드 이동과 소식 읽기를 사용할 수 있다. 연결 설정과 전체화면에서는 해당 화면에 집중하도록 기존 노출 범위를 유지한다.

## 실행 결과

- `npm test`: 240개 통과.
- `node tests/browser/density-preview.mjs`와 `python3 tests/browser/density.py`: 278개 통과. 라이트·다크 각각 320/390/768/1366/1920px, 1366px 창의 실제 탭 확대 200%에서 로그인·사무실·전체화면·업무 보드·검색·인계·연결 설정과 상세창을 점검했다. 글자·조작 최소 크기, 페이지 가로 넘침·모달 닫기·초안 유지·비밀번호 변경과 툴팁 회귀가 포함된다.
- 같은 합성 환경에서 두 테마·다섯 너비의 사무실·회의실·대기실·다과실, 총 40개 방 배치를 추가 측정했다. 움직임 버튼의 오른쪽 정렬, 한 줄 소개의 잘림 없음, 넓은 화면의 맵·설명 위아래 일치와 버튼 가운데 정렬을 1px 이내로 확인했다. 작은 화면은 자연스러운 세로 배치와 페이지 넘침 없음을 확인했다.
- 두 테마·다섯 너비에서 Home·End로 양 끝 방 버튼에 접근하고, 옮긴 데스크에서 업무를 연 뒤 업무 보드로 이동·복귀해 답변 초안이 유지됨을 확인했다. 관리 메뉴를 접어도 소식이 보이며 연결 설정에서는 독립 구역을 숨기고 사무실로 돌아오면 다시 표시한다. JS 오류는 없었다.

- 동작 줄이기를 끈 별도 브라우저에서 오른쪽 움직임 버튼의 켜짐/꺼짐 전환을 확인했다. 전체화면 API가 없는 경우에도 데스크·소식을 숨기고 Escape로 돌아오면 복원한다.

화면과 측정 결과는 Git에서 제외된 `artifacts/density/`, `artifacts/balance/`에 저장했다. 라이트 1366px·다크 320px 사무실 캡처를 직접 확인했다. 테스트 실행 절차는 [개발 안내](development.md#화면-밀도계정-변경-검증)를 따른다. Chromium 검증이며 다른 브라우저 전체 적합성이나 모든 공급자의 실계정 연동을 의미하지 않는다.
