# 활성 프로젝트 층 검증 — 2026-10-30

## 여러 프로젝트의 실제 세션 감지 보정 — 2026-10-31

0.2.6에서는 호스트의 생존 감지가 연결기 실행 폴더와 다른 세션을 제외하고, 직원 등록 시 최상위 프로젝트를 모든 세션에 적용하던 문제를 수정했다. [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server#threads)의 현재 적재 목록과 본문 없는 메타데이터 읽기로 세션별 폴더 이름·해시를 구분한다. 원문 폴더 경로·미리보기·대화는 상태에 남기지 않는다. 공개 대화·검색 수집과 지시 전송은 기존 선택 폴더를 유지한다.

- `npm test`: 254개 통과(Node.js 26.8.1). 추가 회귀 검증은 `tests/server/project-sessions.test.js`, `execution.test.js`, `commands.test.js`에 있다.
- 서로 다른 프로젝트와 같은 이름의 다른 폴더를 감지 → 서버 API → 직원 등록 → 층 생성까지 검증했다. 잘못 배정된 기존 연결의 보정, 별칭·수동 배정 보존, 재시작·연결 소실·재연결, 구버전 호환과 잘못된 메타데이터 제외를 확인했다.
- 다른 프로젝트의 대화 파일 읽기·새 지시 접수·대기 중 지시 전송을 차단하고, 작업 폴더가 바뀐 세션에 이전 공개 대화를 합치지 않는 것을 확인했다.
- `tests/browser/project-floors.py`: 두 테마·320/390/768/1366/1920px·실제 200% 확대의 12개 조합 통과. 층 추가·제거·복원, 초점·초안·확대·전체화면·새로고침과 최종 글자 크기·넘침을 확인했다.
- 실제 연결된 Codex의 읽기 전용 메타데이터도 별도 메모리 사무실에 적용해 세션별 프로젝트 일치와 업무층 분리를 확인했다. 실제 지시 전송·세션 종료·재개는 수행하지 않았다.
- 함께 수정한 로그인 화면은 두 테마·5개 화면 폭에서 파일 위치 안내 제거·배치·최소 글자와 조작 크기를 확인했다. 임시 계정의 최초 비밀번호 변경·일반 변경 화면과 기존 인증 테스트가 통과했고 브라우저 오류는 없었다.
- 커밋 `3bb2359`의 Git 아카이브로 Docker 이미지를 빌드해 0.2.6을 배포했다. health check와 정적 자산 일치, 기존 계정·직원 설정·업무·메모·프로젝트·등록 기록, 환경 변수·마운트·포트·업무 접수 상태 보존을 확인했다. 호스트 연결기도 기존 계정·실행 인수·설정으로 재시작했다.

- CLI·Staff·Projects·OfficeGuide의 사용설명서 원본과 공개 Wiki를 함께 갱신했다(Wiki `7e28544`).

## 수정 범위

이전 화면은 저장한 전체 프로젝트를 그대로 층으로 만들고, 프로젝트 목록이 비어도 기본 업무층을 표시했다. 저장 프로젝트가 두 개이면 활성 세션이 없어도 공용 공간과 함께 네 층이 남았다.

0.2.4는 현재 등록 직원의 생존·연결을 기준으로 표시할 프로젝트를 고른다. CLI는 현재 적재가 확인된 세션만, 프로세스·웹은 연결된 실행 인스턴스·개별 대화만 포함한다. 서비스 화면, 미등록·생존 미확인·보관·연결 소실은 업무층을 만들지 않는다. 배정된 체험 프로젝트는 실제 체험 업무 진행 중에 표시한다. 프로젝트 목록과 기록은 변경하지 않는다.

표시 층은 2층부터 연속 배치하고 방 식별자는 유지한다. 활성 프로젝트가 없으면 공용 두 층만 남는다. 삭제된 방·이동 목적지는 대기실로 정리하며, 남아 있는 방·전체 건물 보기·확대·초안·탐색 초점을 유지한다. 층 재구성 뒤 직원 캐릭터도 다시 배치한다.

## 브라우저 검증

Chromium과 합성 데이터로 두 테마의 320·390·768·1366·1920px 및 실제 200% 브라우저 확대를 확인했다.

- `tests/browser/project-floors.py`: 12개 화면 조합에서 공용 2층 → 활성 프로젝트 2개/전체 4층 → 프로젝트 1개/전체 3층 → 공용 2층 → 재연결을 검증. 이동 버튼·직원 캐릭터·프로젝트 이름·층 번호, 초점·입력 초안·확대·전체 건물 보기·전체화면·새로고침, 최종 글자 크기·44px 조작·페이지 가로 넘침과 브라우저 오류를 확인했다.
- `tests/browser/office-update.py`: 기존 12개 화면 조합에서 로그인·대기실 메모 수정·오프라인 업무/CLI 히스토리·페이지 이동·대화 상세·전체화면·로그아웃을 확인했다. 보관 직원과 지난 프로젝트가 있어도 기본 업무층이 생기지 않도록 기대값을 갱신했다.
- 최종 0.2.4에서 실제 보행 중 층 삭제와 WebGL 사용 불가를 별도로 확인했다. 이전 보행이 완료될 시간이 지나도 대기실 위치가 유지되며, 첫 활성 프로젝트 진입과 빈 건물의 공용 공간 제목을 확인했다.
- 합성 캡처와 결과는 Git 제외 `artifacts/project-floors/`, `artifacts/office-update/`에 저장했다. 두 테마의 데스크톱·모바일 빈 사무실을 직접 확인했다.

검증은 지원 상태를 재현한 합성 기록을 사용했다. 실제 공급자의 업무 실행·세션 종료 명령·지시 전송은 수행하지 않았다. 재현 명령은 [개발 안내](development.md#활성-프로젝트-층-검증)를 따른다.
