# 활성 프로젝트 층 검증 — 2026-10-30

## 수정 범위

이전 화면은 저장한 전체 프로젝트를 그대로 층으로 만들고, 프로젝트 목록이 비어도 기본 업무층을 표시했다. 저장 프로젝트가 두 개이면 활성 세션이 없어도 공용 공간과 함께 네 층이 남았다.

0.2.4는 현재 등록 직원의 생존·연결을 기준으로 표시할 프로젝트를 고른다. CLI는 현재 적재가 확인된 세션만, 프로세스·웹은 연결된 실행 인스턴스·개별 대화만 포함한다. 서비스 화면, 미등록·생존 미확인·보관·연결 소실은 업무층을 만들지 않는다. 배정된 체험 프로젝트는 실제 체험 업무 진행 중에 표시한다. 프로젝트 목록과 기록은 변경하지 않는다.

표시 층은 2층부터 연속 배치하고 방 식별자는 유지한다. 활성 프로젝트가 없으면 공용 두 층만 남는다. 삭제된 방·이동 목적지는 대기실로 정리하며, 남아 있는 방·전체 건물 보기·확대·초안·탐색 초점을 유지한다. 층 재구성 뒤 직원 캐릭터도 다시 배치한다.

## 자동 검증

- Node.js 26.8.1에서 `npm test`: 249개 통과.
- 배포 이미지의 Node.js 24.14.0에서 248개 통과·1개 조건부 제외. 제외된 항목은 다른 비루트 UID를 구성하는 권한 검사이며, 비루트 컨테이너에서는 실행 조건이 충족되지 않는다. 호스트 실행에서는 통과했다. 이미지에는 테스트·개발 자료를 포함하지 않고 검증 시에만 읽기 전용으로 마운트했다.
- `tests/ui/project-floors.test.mjs`: 빈 목록·과거 프로젝트, 미등록·종료·연결 소실·보관, 살아 있는 대기·턴 종료, 같은 프로젝트의 마지막 연결, 수동 배정·웹 서비스 화면·체험 업무, 층 번호 정리와 프로젝트 기록 불변.
- `tests/ui/project-floor-refresh.test.mjs`: 첫 활성 프로젝트 진입, 남은 방·초점·초안·확대, 전체 건물 보기, 이동 중 삭제와 대기 이동 무효화, 생존 프로젝트의 층 번호 변경과 복도 위치.
- 기존 방·경로·활동 테스트는 실제 프로젝트가 있는 명시적 배치를 사용하도록 변경했다. 빈 사무실에서 고정 업무층을 가정하지 않는다.

## 브라우저 검증

Chromium과 합성 데이터로 두 테마의 320·390·768·1366·1920px 및 실제 200% 브라우저 확대를 확인했다.

- `tests/browser/project-floors.py`: 12개 화면 조합에서 공용 2층 → 활성 프로젝트 2개/전체 4층 → 프로젝트 1개/전체 3층 → 공용 2층 → 재연결을 검증. 이동 버튼·직원 캐릭터·프로젝트 이름·층 번호, 초점·입력 초안·확대·전체 건물 보기·전체화면·새로고침, 최종 글자 크기·44px 조작·페이지 가로 넘침과 브라우저 오류를 확인했다.
- `tests/browser/office-update.py`: 기존 12개 화면 조합에서 로그인·대기실 메모 수정·오프라인 업무/CLI 히스토리·페이지 이동·대화 상세·전체화면·로그아웃을 확인했다. 보관 직원과 지난 프로젝트가 있어도 기본 업무층이 생기지 않도록 기대값을 갱신했다.
- 합성 캡처와 결과는 Git 제외 `artifacts/project-floors/`, `artifacts/office-update/`에 저장했다. 두 테마의 데스크톱·모바일 빈 사무실을 직접 확인했다.

검증은 지원 상태를 재현한 합성 기록을 사용했다. 실제 공급자의 업무 실행·세션 종료 명령·지시 전송은 수행하지 않았다. 재현 명령은 [개발 안내](development.md#활성-프로젝트-층-검증)를 따른다.
