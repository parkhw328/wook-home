# 프로젝트 층과 작업 히스토리

0.2.0부터 한 업무 층에는 하나의 프로젝트만 배치합니다. 맵 하단의 **층 번호 · 방 아이콘**을 누르면 전용 사무실과 회의실로 이동합니다. 마우스를 올리거나 키보드로 초점을 두면 프로젝트·방 전체 이름을 확인할 수 있고, 터치에서는 한 번 눌러 이동하면서 이름을 봅니다. 공용 대표이사실은 가장 높은 층이며, 1층에는 휴게실·대기실·다과실이 있습니다.

0.2.4부터 **활성 연결이 확인된 프로젝트만 업무층을 표시**합니다. 같은 프로젝트의 마지막 활성 세션이 사라지거나 보관되면 업무층과 이동 버튼도 없어집니다. 활성 프로젝트가 없으면 **1층 공용 라운지와 2층 대표이사실**만 남습니다. 살아 있는 CLI는 한 번의 답변을 마치거나 입력을 기다려도 층을 유지합니다. 연결 확인 실패는 실제 실행 종료를 뜻하지 않습니다.

연결이 다시 확인되면 프로젝트 층이 나타납니다. 층이 없어져도 직원·별칭·메모·담당 프로젝트·지난 업무·보관 대화는 유지됩니다. 해당 방에 있었다면 대기실로 이동하며, 남아 있는 방의 선택과 작성 중인 내용·확대·전체 건물 보기는 유지합니다.

## 프로젝트 배정

- 지원 CLI의 실제 작업 폴더가 확인되면 해당 폴더를 층 배치에 우선합니다. 같은 이름의 다른 폴더도 구분하며 개인 경로 원문을 노출하지 않습니다.
- 직원 설정 또는 대기실의 메모 창에서 **담당 프로젝트**를 입력해 저장합니다. 연결된 CLI 프로세스·웹 대화 또는 진행 중인 체험 업무가 있으면 수동 프로젝트 층을 표시합니다. 배정 이름만 입력하거나 웹의 새 대화·서비스 화면을 연결한 경우에는 층을 만들지 않습니다. 같은 이름의 수동 배정은 같은 층을 사용합니다.
- 관찰한 폴더와 수동 배정은 구분됩니다. 담당 이름 변경은 CLI 폴더 변경이나 실행 세션 이동이 아닙니다. 실제 작업 폴더가 연결된 직원은 그 폴더 층에 남습니다.
- 프로젝트 식별자와 기존 순서는 로컬에 유지합니다. 화면의 업무층은 활성 프로젝트만 2층부터 연속으로 배치하므로 세션 변화에 따라 표시 번호는 바뀔 수 있습니다. 기존 업무 기록의 프로젝트는 바뀌지 않습니다. 미배정 직원은 대기실에서 프로젝트를 배정할 수 있습니다.
- 호스트 연결기 하나는 실행할 때 지정한 작업 폴더 하나를 관찰합니다. 여러 프로젝트의 실제 CLI를 동시에 수집하는 기능은 이 버전에 포함되지 않습니다. 다른 프로젝트에서 관찰했던 직원·배정·보관 기록은 유지합니다.

기존 연결기는 한 번 업데이트·재실행해야 폴더 식별값이 전달됩니다. 저장소 이름을 추측해 다른 폴더의 직원과 합치지 않습니다.

## 대기실에서 다음 작업 준비

1. **1F 대기실**에서 보관하거나 연결을 확인할 직원을 선택합니다.
2. **보관 · 복귀 · 메모**에서 담당 프로젝트와 다음 행동을 작성합니다.
3. **대기실에 보관 · 메모 저장** 또는 **메모 저장 · 사무실로 복귀**를 선택합니다.
4. 연결이 사라졌다면 직원 상세에서 현재 감지 대상을 직접 다시 연결합니다.

기존 창고의 메모와 보관 상태를 그대로 유지합니다. 복귀·재연결은 실제 CLI 재개나 이전 지시 재전송을 하지 않습니다.

## 다과실에서 지난 작업 보기

**1F 다과실 → 작업 히스토리 보기**에서 업무, CLI 보관 대화, 사무실 활동을 조회합니다. 프로젝트·종류·제목 검색과 20건씩 페이지 이동을 제공하며 **업무보고 보기**, **지난 대화 읽기**로 상세를 엽니다. 다른 프로젝트의 이전 로컬 보관 기록도 프로젝트를 직접 선택해 확인할 수 있습니다.

CLI 히스토리는 **연결 설정 → CLI 검색 보관**을 켜 수집했던 공개 메시지 사본입니다. 원래 CLI가 꺼지거나 서버를 재시작해도 유지합니다. 과거에 보관하지 않은 대화·공급자 계정 전체는 자동 복원하지 않습니다. 수집 실패·한도·일부 기록 여부를 표시하며, 현재 세션 종료·업무 완료와 보관 여부는 별개입니다. 사무실 활동은 기존 최근 200건 범위이며 업무는 저장된 전체 목록을 조회합니다.

기록 원문과 인증 정보는 Git·이미지·공개 Wiki에 포함되지 않습니다. CLI 검색 사본은 업무 인계와 분리됩니다.
