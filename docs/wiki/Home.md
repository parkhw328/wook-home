# wook-home 사용설명서

여러 AI 에이전트를 직원처럼 모아 업무를 지시하고 결과를 확인하는 가상 회사입니다. 사용자는 Commander로서 업무 우선순위와 최종 판단을 담당합니다.

## 현재 제공 범위

0.1.0-dev는 로컬 체험 버전입니다. 직원 등록, 체험 업무 지시, 질문 답변, 결과 승인·취소, 일시 중지와 인계 JSON 내보내기를 제공합니다. 체험 직원은 정해진 안내 문구로 동작하며 실제 AI를 호출하지 않습니다.

기존 로컬 Codex는 [연결 프로그램](CLI.md)으로 활동을 관찰하고 **실제 지시를 전송**할 수 있습니다. **연결 설정 → 공개 대화 읽기**를 켜고 저장하면 최근 공개 대화를 사무실에서 읽습니다. 승인·중단은 원래 Codex에서 처리합니다. 연결한 Codex 직원은 [모델·추론 강도 선택](Models.md)과 지시 전송을 지원합니다. 새 실제 AI 직원 실행, 다른 공급자 실행과 인계 가져오기는 준비 중입니다. 도움말은 [GitHub Wiki](https://github.com/parkhw328/wook-home/wiki)에 게시합니다.

## 설치와 접속

1. Windows는 Docker Desktop의 Linux 컨테이너, Linux는 Docker Engine과 Compose를 시작합니다. [Linux 준비·감지 안내](Linux.md).
2. 저장소 루트에서 `docker compose up --build -d`를 실행합니다.
3. 브라우저에서 http://localhost:8080 에 접속합니다.

계정과 API 키가 없어도 체험할 수 있습니다. 기본 포트가 사용 중이면 `.env.example`을 `.env`로 복사하고 `WOOK_PORT`를 사용 가능한 포트로 바꾼 뒤 다시 실행하세요. 접속 주소에도 변경한 포트를 사용합니다.

## 사무실 이름과 화면

기본 이름은 **StackQueue Office**입니다. `.env`에서 `OFFICE_NAME=나의 사무실`처럼 1~80자의 이름을 지정하고 `docker compose up -d`로 적용합니다. 직원·업무 데이터는 보존됩니다.

한글은 Noto Sans KR, 영문·숫자는 JetBrains Mono를 서버에서 직접 제공합니다. 별도 폰트 설치나 외부 폰트 서버 연결은 필요하지 않습니다. 레드 계열 사무실에서 복도를 따라 방에 입장하고, 사무실·회의실·대표이사실에서 지시·답변·업무보고를 이어갑니다. 휴게실·다과실도 독립된 공간입니다. 화면 동작과 관찰 세션에 대한 설명은 [화면 사용법](UI.md)을 참고하세요.

## 첫 업무 체험

1. 직원 등록에서 이름과 역할을 입력하고 공급자로 `체험 직원`을 선택합니다.
2. 등록한 직원을 선택하고 업무 제목과 설명을 입력합니다.
3. 직원의 체험용 질문에 답합니다.
4. 결과가 실제 AI 작업이 아닌 체험 안내임을 확인하고 승인합니다. 필요하면 미완료 업무를 취소할 수 있습니다.

직원별로 하나의 미완료 업무만 진행합니다. 다른 업무를 시작하려면 기존 업무를 완료하거나 취소합니다.

## 중지와 재개

화면에서 사무실을 일시 중지하면 새 업무와 답변·승인이 멈추고 진행 상태가 저장됩니다. 이후 재개하면 이전 단계로 돌아갑니다.

새 Codex 지시 접수도 중지됩니다. 이미 전달한 지시와 실행 중인 호스트 Codex는 원래 터미널에서 직접 중지해야 합니다.

```powershell
docker compose stop
docker compose up -d
```

컨테이너 종료 전에도 미완료 업무를 일시 중지합니다. 재시작 후 화면에서 재개하세요. 직원과 업무는 `office-data` 볼륨에 보존되므로 데이터 삭제를 의도하지 않았다면 `docker compose down -v`를 사용하지 마세요.

## PC를 이동할 때

작업을 중지하고 인계 JSON을 내려받아 내용을 확인합니다. 이 파일에는 입력한 업무·대화가 포함되므로 공개하거나 GitHub에 올리기 전에 검토하세요. 앱은 자동으로 커밋·푸시하지 않습니다.

외부 Codex와 연결 프로그램을 사용했다면 해당 PC의 터미널에서도 각각 작업을 종료하세요. Docker 종료나 사무실 일시 중지가 외부 프로세스를 중지하지는 않습니다.

다른 PC에서는 GitHub의 코드로 같은 환경을 실행할 수 있습니다. 단, 그 PC의 볼륨은 별개이며 현재는 인계 JSON을 읽어 수동으로 업무를 다시 등록해야 합니다. 원래 세션이나 데이터를 자동 복원하는 기능은 후속 개발 대상입니다.

## 문제 해결

- 접속되지 않음: Docker가 실행 중인지와 `docker compose ps`의 상태를 확인합니다.
- 화면 업데이트가 보이지 않음: `docker compose up --build -d`로 다시 빌드합니다.
- 업무를 진행할 수 없음: 사무실 중지 여부, 공급자가 체험 직원인지, 직원의 미완료 업무가 있는지 확인합니다.
- 연결 끊김 표시: 서버를 다시 실행하고 연결이 복구된 뒤 재개합니다.
- 외부 PC에서 접근되지 않음: 기본값은 로컬 전용입니다. [네트워크 접속 설정](Linux.md#다른-pc에서-접속)의 바인딩 주소·서버 주소 허용 목록을 지정하세요. 사용자 인증과 클라우드 운영은 후속 범위입니다.
