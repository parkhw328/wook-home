# 실행 중인 Codex를 사무실에서 보기

현재는 **읽기 전용 관찰**을 제공합니다. 호스트 PC에서 실행한 연결 프로그램이 선택한 프로젝트의 Codex 기록을 확인하고, 사무실에 세션별 최근 활동을 표시합니다. 별도의 AI 호출이나 API 키는 필요하지 않습니다.

## 연결하기

Docker가 실행되는 PC에 Node.js 24.14 이상(27 미만)과 로컬 Codex 세션 기록이 필요합니다. 저장소 루트에서 두 명령을 실행하세요.

```powershell
docker compose up --build -d
npm run bridge:codex -- --workspace .
```

두 번째 명령은 실행한 터미널에 계속 두세요. http://localhost:8080 에서 약 5초 안에 이 프로젝트의 세션이 표시됩니다. 이미 켜둔 Codex를 재시작할 필요는 없습니다. 관찰을 끝내려면 연결 프로그램의 터미널에서 `Ctrl+C`를 누르세요. 약 20초 후 화면에 연결 끊김이 표시됩니다. Codex 자체는 계속 실행됩니다.

다른 프로젝트를 관찰하려면 `--workspace "C:\Project\other-project"`처럼 정확한 작업 폴더를 지정합니다. 한 사무실에는 연결 프로그램 하나만 실행하세요. PC를 옮기면 해당 PC에서도 별도로 실행해야 합니다.

## 상태 읽기

| 표시 | 의미 |
| --- | --- |
| 최근 활동 | 작업 시작·도구·응답 등의 이벤트가 기록됨 |
| 턴 종료 | 한 번의 응답이 끝났다는 기록. 전체 업무 완료를 뜻하지 않음 |
| 중단 | 턴 중단 이벤트가 기록됨 |
| 상태 확인 필요 | 활동 기록이 120초 넘게 갱신되지 않음. 긴 추론 중일 수도 있음 |
| 연결 끊김 | 연결 프로그램의 상태 갱신이 20초 넘게 중단됨 |

사무실의 일시 중지·재개는 체험 업무에만 적용됩니다. 관찰 중인 외부 CLI의 지시·Q&A·중단·모델 변경은 원래 터미널에서 하세요. 화면에서의 제어와 신규 실제 AI 채용은 후속 기능입니다.

## 관찰 범위와 데이터

- 기본 기록 위치는 `CODEX_HOME/sessions`, 설정하지 않았다면 사용자 홈의 `.codex/sessions`입니다. `--sessions-dir`로 다른 기록 폴더를 지정할 수 있습니다.
- 최근 7일 안에 생성되고 최근 24시간 내 갱신된 기록 중 선택한 작업 폴더와 정확히 일치하는 세션을 최대 24개 표시합니다. 다른 프로젝트와 오래된 세션은 표시되지 않습니다.
- 현재 Codex 0.162.1의 로컬 JSONL 기록으로 확인한 실험적 어댑터입니다. 기록 형식 변경, 다른 호스트·WSL에 저장된 세션은 추가 대응이 필요할 수 있습니다. 프로세스 생존 여부를 확인하는 감시 도구는 아닙니다.
- 호스트에서 메타데이터와 이벤트 종류를 추려 `data/bridge/codex.json`으로 전달합니다. 대화·프롬프트·도구 출력·계정 정보·인증 파일은 전달하지 않습니다. 전체 기록이나 홈 디렉터리를 Docker에 연결하지 않습니다.
- 상태 파일은 Git과 Docker 이미지에서 제외되며, 실행 시 전용 폴더만 읽기 전용으로 마운트합니다. SQLite나 인계 JSON에도 관찰 기록을 저장하지 않습니다.
- `npm run bridge:codex -- --workspace . --once`는 한 번만 수집하는 진단 명령입니다. 계속 관찰하려면 `--once`를 빼세요.

## 문제가 있을 때

- 세션이 없음: Codex를 실행한 작업 폴더와 `--workspace`가 같은지, 기록이 위 범위 안에 있는지 확인합니다.
- 연결 끊김: 연결 프로그램이 실행 중인지 확인합니다. 컨테이너 재빌드만으로 호스트 연결 프로그램이 시작되지는 않습니다.
- Linux에서 상태를 읽지 못함: `data/bridge` 폴더와 JSON을 컨테이너 사용자(uid 1000)가 읽을 수 있는지 확인합니다. 인증 폴더 전체의 권한을 바꾸지 마세요.

실시간 명령·승인 기능은 별도의 제어권 설계가 필요합니다. 공식 [Codex App Server](https://learn.chatgpt.com/docs/app-server)는 스레드와 턴 제어 인터페이스를 제공하지만, 이 관찰 기능은 App Server 연결이나 기존 터미널 세션의 제어권 인수가 아닙니다.
