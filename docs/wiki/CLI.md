# 로컬 Codex 연결과 업무 지시

이미 실행 중인 Codex를 사무실에서 보고 **선택한 세션에 다음 지시를 전송**할 수 있습니다. 호스트 연결 프로그램이 공식 큐로 전달합니다. 모델·강도를 선택하면 공식 App Server의 다음 실행 설정을 먼저 변경합니다. 기존 Codex 계정·권한을 사용하며 API 키를 Docker에 넣지 않습니다. 관찰만 사용하면 AI 호출이 발생하지 않습니다.

## 연결 설정으로 시작하기

1. 왼쪽 **연결 설정**을 엽니다. 직원 · 연결 관리의 **연결 관리 → 설정**으로도 들어갈 수 있습니다.
2. **공개 대화 읽기**, **CLI 대화 검색 보관**, **Codex 지시 전송** 중 필요한 기능을 선택하고 **설정 저장**을 누릅니다. 최초에는 모두 꺼져 있습니다. 대화 읽기만 필요하면 나머지는 켜지 않아도 됩니다.
3. **연결 프로그램 실행 대기**라면 화면 아래 실행 안내를 펼칩니다. Docker가 실행되는 PC에서, CLI를 사용하는 계정으로 이 저장소 폴더의 별도 터미널을 엽니다. Node.js 24.14 이상(27 미만)이 필요합니다.

```powershell
npm ci
npm run bridge:codex -- --workspace .
```

명령은 화면에서 복사할 수 있습니다. 이 터미널을 켜 두고 사무실에서 적용 상태를 확인하세요. 서버가 아직 실행되지 않았다면 다른 터미널에서 `docker compose up --build -d` 후 http://localhost:8080 을 엽니다. 다른 프로젝트는 마지막 `.` 대신 해당 폴더 경로를 지정합니다. 지시 전송에는 로그인된 Codex와 `codex queue` 지원이 필요합니다.

**이후 설정 변경에는 연결 프로그램 재시작이 필요 없습니다.** 선택하고 저장하면 보통 5초 안에 반영하며 화면이 다음 갱신에서 적용을 확인합니다. 검색 자료는 별도 수집 주기(약 30초)를 기다릴 수 있습니다. 저장 성공을 적용 완료로 표시하지 않으며 연결이 끊겨도 선택은 유지합니다.

**이전 연결 프로그램** 안내가 나오면 최신 코드를 받은 뒤 해당 터미널에서 Ctrl+C로 연결기만 종료하고 위 명령을 다시 실행하세요. 기존 Codex 자체를 재시작할 필요는 없습니다. 한 사무실에는 연결기 하나를 실행하며 PC를 옮기면 새 PC에서도 실행합니다.

### 기존 옵션을 사용하던 경우

`--include-conversations`는 원래 **연결 프로그램 시작 명령 뒤에** 붙여 대화 읽기를 켜는 옵션입니다. Codex 시작 명령이나 Docker 명령에 붙이지 않습니다. 이제 기본 사용 흐름에서는 옵션을 추가할 필요 없이 화면에서 선택합니다.

호환 옵션 `--include-conversations`, `--include-search-history`, `--allow-commands`는 **화면에서 저장한 설정이 없을 때만** 초기값으로 사용합니다. 한 번 저장하면 화면 설정이 우선하며, 이후 옵션을 빼고 실행해도 저장된 선택을 유지합니다. 기능을 끄려면 화면에서 해제하고 저장하세요.

설정은 `data/bridge/commands/bridge-settings.json`에 별도로 저장합니다. Git·이미지·업무 인계에는 포함하지 않습니다. 다른 화면에서 동시에 수정하면 충돌을 알리고, 자동 갱신은 작성 중인 선택을 덮어쓰지 않습니다.

## 새 창이 지시할 대화 목록에 보이지 않을 때

Windows와 Linux의 **감지된 CLI · 웹 탭**에는 첫 메시지 전의 새 CLI도 나타납니다. 지시할 대화 목록은 활동 기록의 세션 ID를 사용하므로 원래 Codex에서 첫 대화를 시작해야 표시됩니다.

1. 연결 프로그램에 지정한 작업 폴더에서 Codex를 시작합니다. 예: 저장소 루트에서 `codex --cd .`를 실행하거나 Codex 앱에서 같은 프로젝트를 선택합니다.
2. 원래 Codex 창에서 `연결 확인입니다. 파일을 수정하지 말고 준비됐다고 한 줄로 답해 주세요.`처럼 첫 메시지를 보냅니다.
3. 활동 기록이 생성된 뒤 약 5초의 수집 주기와 화면 갱신을 기다립니다. 8080의 **이 PC의 CLI 세션**에서 ID 뒷자리를 확인합니다.
4. 해당 세션을 선택하고 **이 세션에 지시**를 누릅니다. 이미 작업 중이면 새 지시는 현재 턴 뒤에 처리됩니다.

ChatGPT 웹에 로그인하거나 새 브라우저 탭을 여는 것만으로 연결되지는 않습니다. ChatGPT 계정으로 로그인한 **로컬 Codex 앱·CLI**에서 대화를 시작해야 합니다. 사무실의 ChatGPT 열기 버튼은 공식 웹 서비스 접속 링크입니다.

직원 채용으로 등록한 OpenAI 직원과 **이 PC의 CLI 세션**도 서로 다릅니다. 직원 상세의 **지시할 Codex 대화 연결**로 대상을 명시하면 직원에게 모델·강도를 선택해 지시할 수 있습니다. 답변·승인 요청은 원래 Codex 창에서도 확인합니다. **공개 대화 읽기**를 켜면 사무실의 대화 터미널에서 제한된 최근 공개 응답을 읽을 수 있습니다.

## CLI가 열리고 닫힐 때

연결 프로그램은 약 5초마다 Windows에서는 같은 로그인 세션, Linux에서는 같은 사용자(유효 UID)의 지원 CLI 프로세스를 확인합니다. Linux의 다른 터미널·SSH 로그인도 같은 사용자라면 감지합니다. **첫 메시지를 보내기 전의 빈 CLI 창도 프로세스 목록에 나타납니다.** 창을 닫거나 프로세스가 끝나면 종료로 바뀌고 최근 종료 목록에 최대 10분간 남습니다. 새 실행은 PID와 시작 시각으로 구분합니다.

프로세스 감지만 사용하려면 `npm run bridge:codex -- --workspace .`로 실행합니다. Codex 로그인이나 저장 대화 폴더가 없어도 시작할 수 있습니다.

현재 Codex의 네이티브 실행 파일, Claude Code 네이티브·공식 npm 진입점, Gemini CLI 공식 npm 진입점을 분류합니다. Codex 실제 실행·종료는 이 PC에서 검증하고, 미설치인 Claude·Gemini는 분류 자동 테스트와 실제 실행 검증을 구분합니다. `queue`, 서버·업데이트·인증 보조 명령과 비대화형 실행은 대화 CLI 수에 포함하지 않습니다.

프로세스 목록은 **이 PC 범위**, 대화 목록은 **선택한 프로젝트 범위**입니다. 프로세스와 대화 ID를 추정해서 합치지 않습니다. CLI 창이 닫혀도 저장된 대화는 남으며 별도로 확인할 수 있습니다. 프로세스 감지는 AI 로그인·업무 완료·명령 전송 가능 여부를 보장하지 않습니다.

프로세스 조회가 실패하면 확인 필요로 표시하고, 연결 프로그램이 끊기면 마지막 관찰임을 알립니다. 활동 기록이 오래되었다는 이유로 종료 처리하지 않습니다. Windows·Linux 이외에서는 프로세스 감지 미지원으로 표시하고 기존 대화 관찰을 유지합니다. 프로세스의 명령 원문·실행 경로·계정 정보는 웹에 전달하지 않습니다. Linux의 준비 사항과 권한 문제는 [Linux 안내](Linux.md)를 확인하세요.

## 대화창 닫기와 이어 읽기

위쪽 **닫기 ×**, Escape 또는 창 바깥 클릭으로 언제든 대화창을 닫습니다. 긴 대화와 작은 화면에서도 닫기 버튼은 본문과 별도로 유지됩니다. 현재 탭에서 다시 열면 세션별 검색·작성자 필터·읽던 위치가 복원됩니다. 작은 화면의 **세션 · 검색 · 작성자 필터**는 접힌 상태로 시작합니다.

직원 정보·지시 화면으로 이동하면 기존 대화창을 교체합니다. 작성 중인 지시와 선택한 모델·강도는 창을 다시 열 때 유지됩니다. 창을 닫는 동작은 CLI 실행이나 이미 보낸 지시를 중단하지 않습니다. 방 아래 대화·업무 패널은 **화면 닫기 ×**와 **대화·업무 다시 열기**로 접고 펼칩니다.

## 모델·추론 강도 선택

직원 상세 또는 세션 지시 화면에서 **추론 모델 → 추론 강도 → 전달할 지시**를 선택합니다. 모델 목록은 호스트 Codex의 실제 `model/list` 응답이며 모델별 지원 강도만 표시합니다. 기존 설정을 쓰려면 **현재 CLI 설정 유지**를 선택하세요. 지원 연결은 `thread/settings/update` 후 `thread/queue/add`를 수행합니다. Codex CLI/App Server 0.163.0의 인터페이스로 확인했으며 구버전이 설정 변경을 거절하면 지시는 보내지 않습니다. [상세 적용 범위와 접수 상태](Models.md).

## 지시 전송과 결과 확인

1. **이 PC의 CLI 세션**에서 프로젝트와 세션 ID 뒷자리를 확인하고 대상을 선택합니다.
2. 대화 터미널 위의 **이 세션에 지시**를 누르고 해야 할 일을 입력해 전송합니다. 최대 4000자입니다.
3. **Codex 접수**를 확인합니다. 작업 완료가 아니라 공식 큐에 들어갔다는 뜻입니다. 진행 중인 턴 뒤에 처리될 수 있습니다.
4. 공개된 사용자 지시와 응답은 사무실의 대화 터미널에서 확인합니다. 실제 파일 수정 결과·승인 요청·중단은 원래 Codex 화면이나 터미널에서 확인합니다.

같은 요청 ID로 재시도하면 기존 접수 기록을 반환하여 중복 전송하지 않습니다. **전송 확인 필요**는 접수 여부를 확정하지 못한 상태입니다. 원래 Codex에서 확인한 뒤 새 지시를 보내세요. 시간 초과·재시작 시 자동 재전송하지 않습니다.

사무실 일시 중지는 체험 업무와 새 지시 접수를 막습니다. **이미 접수된 지시나 외부 Codex 실행은 중단하지 않습니다.** 중단·승인은 원래 Codex에서 처리하세요. [모델·추론 강도](Models.md)는 직원 상세나 세션 지시 화면에서 선택하며 다음 실행부터 적용합니다. 새 실제 AI 세션 채용과 다른 공급자의 명령 전달은 후속 범위입니다.

## 대화기록 범위와 보관

세션 목록·CLI 캐릭터·방 안의 세션을 클릭하면 대화기록 모달이 즉시 열립니다. 세션 전환, 검색·역할 필터, 최신 기록 이동과 지시 화면을 같은 창에서 이용하세요. 아래 작업 패널로 스크롤할 필요가 없으며 Esc로 닫은 뒤에도 검색 조건·읽던 위치를 유지합니다. 이전·종료된 세션은 별도의 [자료 검색](Search.md)에서 찾습니다. 검색 보관을 사용하려면 **연결 설정 → CLI 대화 검색 보관**을 켜고 저장합니다.

**공개 대화 읽기**는 선택한 작업 폴더의 사용자 지시·공개 에이전트 응답만 읽습니다. 최근 7일 폴더 중 24시간 내 갱신된 세션의 로그 끝 1MB를 확인하고, 세션당 최대 60개·총 24,000자·메시지당 4,000자로 제한합니다. 이전 기록 또는 긴 메시지가 생략되면 화면에 표시합니다. 전체 과거 기록의 검색이나 복원 기능은 아닙니다.

시스템·개발자 지침, 내부 추론, 도구 호출·출력, 계정 메타데이터는 포함하지 않습니다. 알려진 인증 정보와 개인 경로·이메일·전화번호 패턴은 마스킹합니다. 임의의 모든 민감 문장을 자동 판별하지는 않습니다. 최근 기록 파일은 `data/bridge/conversations`에 별도로 보관하고, 로컬 동일 출처 API를 통해 선택한 세션만 읽습니다. `/api/state`, 업무 DB, 인계 JSON, Git·Docker 이미지에는 본문을 넣지 않습니다. 별도로 켠 검색 보관은 전용 로컬 DB를 사용합니다.

터미널의 검색은 수집된 최근 기록 안에서만 동작합니다. 최초에는 대화 수집이 꺼져 있으며, 다시 끄려면 **연결 설정 → 공개 대화 읽기**를 해제하고 저장합니다. 다음 수집 때 내보낸 대화 파일을 삭제하며 원래 Codex 로그는 변경하지 않습니다. 연결기 종료나 네트워크 단절은 기록이 완료되었다는 뜻이 아니며 마지막 수신 내용임을 표시합니다.

## 직접 연결하거나 지시하기

다른 프로젝트는 `--workspace "C:\Project\other-project"`처럼 Codex의 정확한 작업 폴더를 지정합니다. 기본 기록은 `CODEX_HOME/sessions`, 미설정 시 사용자 홈의 `.codex/sessions`입니다. 다른 기록 위치는 `--sessions-dir`로 지정합니다.

공식 CLI에서도 직접 지시할 수 있습니다.

```powershell
codex queue --thread <세션-UUID> --message "현재 작업을 마친 뒤 테스트 결과를 정리해 줘."
```

별도 App Server를 사용한다면 연결 프로그램에 `--remote <주소>`로 **본인이 관리하는 해당 Codex 서버**를 지정할 수 있습니다. 토큰이 필요한 서버는 호스트 환경 변수에 값을 넣고 `--remote-auth-token-env WOOK_CODEX_TOKEN`처럼 변수 이름만 전달합니다. 토큰을 웹 입력창·저장소·명령 인수에 직접 넣지 마세요. 엔드포인트와 인증을 자동 탐색하거나 생성하지 않습니다. 이 옵션은 기본 로컬 연결과 별도로 검증해야 합니다. WSL의 Codex는 연결 프로그램도 같은 WSL 환경에서 실행하세요.

CLI 자동 발견이 안 되면 `--codex-bin "C:\도구\codex.exe"`처럼 실행 파일이나 공식 npm `bin/codex.js` 경로를 지정합니다. `.cmd`·`.bat`·`.ps1`은 받지 않습니다. 한글·따옴표를 셸 명령으로 해석하지 않도록 인수를 직접 전달합니다.

| 최근 활동 | 작업·도구·응답 이벤트가 기록됨 |
| 턴 종료 | 한 번의 응답 종료. 전체 업무 완료를 뜻하지 않음 |
| 상태 확인 필요 | 활동 기록이 120초 넘게 갱신되지 않음. 긴 추론일 수도 있음 |
| 연결 끊김 | 연결 프로그램 갱신이 20초 넘게 중단됨 |
| 전달 대기 / 전달 중 | 호스트 연결 프로그램 대기 / 공식 CLI 호출 중 |
| Codex 접수 | 공식 CLI가 큐 접수 성공을 반환함 |
| 전달 실패 / 만료 | CLI 거절, 대상 사라짐, 연결 프로그램 재시작 또는 60초 초과 |

연결 프로그램 터미널의 `Ctrl+C` 또는 별도 터미널의 다음 명령으로 종료합니다.

```powershell
npm run bridge:codex -- --stop
```

새 전달을 멈추고 진행 중인 CLI 접수 호출을 정리한 뒤 종료합니다(최대 약 16초). Codex 자체는 종료하지 않습니다. PC 이동 전 원래 Codex에서도 작업을 마무리하거나 중단하세요.

## 데이터와 문제 해결

- 최근 7일 안에 생성되고 최근 24시간 내 갱신된 기록 중 작업 폴더가 일치하는 세션을 최대 24개 표시합니다. Codex 0.162.1·0.163.0의 JSONL 기록으로 검증한 실험적 어댑터이며 프로세스 생존 판정은 아닙니다.
- 상태 JSON에 대화·도구 출력·계정 정보를 넣지 않습니다. Docker에 인증 폴더나 홈 디렉터리를 연결하지 않습니다.
- 전송할 지시 원문은 `data/bridge/commands`에 임시 저장하고 CLI 호출 직전에 제거합니다. 접수 상태와 중복 검사값은 명령 연결 프로그램이 실행되는 동안 7일 뒤 정리합니다. 연결 프로그램이 꺼져 있으면 정리도 중단됩니다. 이 폴더는 Git·이미지·인계 JSON에서 제외합니다.
- Docker는 상태 폴더를 읽기 전용으로, 지시 폴더만 읽기·쓰기로 연결합니다. Linux에서는 연결 프로그램을 먼저 실행해 폴더를 만들고 호스트 사용자와 컨테이너 uid 1000의 접근 권한을 맞추세요.
- 세션이 없음: 새 Codex 창에서 첫 메시지를 보냈는지, 연결 프로그램과 세션의 작업 폴더가 정확히 일치하는지 확인합니다. 다른 폴더·WSL·다른 `CODEX_HOME`의 기록은 자동 합쳐지지 않습니다. 명령 비활성화: **연결 설정 → Codex 지시 전송**의 선택·적용 상태, `codex queue --help`, 사무실 중지 여부를 확인합니다.
- 전달 실패: 원래 터미널에서 위 `codex queue` 명령으로 해당 UUID에 연결되는지 확인합니다. 별도 앱·daemon의 세션은 기록이 있어도 명령 대상 서버가 다를 수 있습니다.
- 지시가 오래 대기함: 연결 프로그램이 켜져 있는지 확인합니다. 시간 초과·재시작 요청은 만료되며 자동 실행하지 않습니다.
- 기록 1000개 제한: 두 프로그램을 중지하고 완료된 지시 기록만 정리합니다. 삭제한 ID는 중복 검사가 불가능하므로 재사용하지 않습니다.
- **설정 저장 실패 / 적용 대기 지속**: 서버와 연결기가 같은 `commands` 폴더를 읽고 쓰는지 확인하세요. Linux에서는 호스트 계정과 컨테이너의 UID·GID를 맞춥니다. 읽기 권한이 없거나 파일이 손상되면 연결기는 기능을 자동으로 켜지 않습니다. 기존 대기 지시는 설정 변경 뒤 자동 재전송하지 않습니다.
- 한 번만 관찰하려면 `npm run bridge:codex -- --workspace . --once`를 사용합니다. 실행 중인 연결 프로그램을 먼저 종료하세요.

공식 참고: [Codex queue 명령](https://learn.chatgpt.com/docs/developer-commands), [Codex App Server](https://learn.chatgpt.com/docs/app-server). 기존 세션을 별도로 resume하지 않고 공식 큐를 사용하며, 실행 중인 터미널의 제어권을 인수하지 않습니다.
