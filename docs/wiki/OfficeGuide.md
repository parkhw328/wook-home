# StackQueue Office 빠른 안내

Commander는 직원을 등록하고 업무를 맡긴 뒤, 질문에 답하고 결과를 확인합니다. 처음에는 체험 직원으로 흐름을 익혀 보세요.

## 세션을 직원으로 사용하기

현재 프로젝트에서 살아 있는 Codex 세션은 직원으로 바로 등록됩니다. **직원 · 연결 관리 → 별칭 · 직원 설정**에서 이름을 붙이고 카드에 마우스를 올려 전체 **session-id**로 세션을 구별하세요. 키보드 초점이나 상세창의 **ID** 버튼으로도 확인할 수 있습니다. 미등록 대상은 별도 등록 대기 목록에서 직접 등록합니다. 등록된 살아 있는 직원은 턴 종료 후에도 사무실에 남으며, 연결 소실·생존 미확인 직원과 보관 업무는 대기실에서 확인합니다. [자세한 직원 사용법](Staff.md).

## 1. 사무실 열기

Windows에서는 Docker Desktop, Linux에서는 Docker Engine을 실행하고 저장소에서 다음 명령을 입력합니다. [Linux CLI·웹 감지 준비](Linux.md)도 참고하세요.

```powershell
docker compose up --build -d
```

http://localhost:8080 에 접속해 admin으로 로그인하고 첫 비밀번호를 변경합니다. [로그인 안내](Login.md)를 참고하세요. 기본 사무실 이름은 StackQueue Office이며 `.env`의 `OFFICE_NAME`으로 바꿀 수 있습니다.

## 2. 첫 직원과 업무

1. **직원 채용**에서 이름·역할을 입력하고 **체험 직원**을 선택합니다.
2. 입체 건물의 **담당 프로젝트의 사무실**에 입장한 뒤 **업무 지시**를 누릅니다.
3. **최상층 대표이사실**에서 질문 발표를 확인하고 답변한 뒤, 업무보고와 대화를 검토해 결과를 승인합니다. **프로젝트 회의실**에서는 지원되는 세션 간 협업을 확인합니다. [협업과 발표](Activity.md)의 감지 범위와 동작을 참고하세요.
4. **복도로 나오기**로 같은 층의 복도에 퇴실합니다. **1F 휴게실·대기실·다과실**도 방문할 수 있습니다. 대기실에서는 보관 업무와 연결 확인이 필요한 직원·CLI를 확인합니다. 기본 화면은 2층 내부이며 맵 하단의 방 버튼으로 이동하거나 **전체 건물**로 모든 프로젝트 층을 함께 볼 수 있습니다.

**전체화면**으로 사무실을 넓게 펼치고, 방 버튼으로 해당 층의 내부 통로와 가구를 가까이 볼 수 있습니다. **＋ / −**, **화면 맞춤**, **동선 표시**를 사용해 둘러보세요. **업무 패널 ↓**는 선택한 방의 작업 화면으로 이동하며 전체화면을 닫아도 방과 대화 선택은 유지됩니다.

방 안의 **사무실 전체 현황**에서 직원 수나 업무 건수를 누르면 해당 목록이 열립니다. 이름·업무를 선택해 직원 상세 또는 업무보고를 확인하세요. 현재 사용자·역할과 서버 연결 상태는 왼쪽 탐색 영역 맨 위에서 함께 확인하고, 도움말·버전은 하단에서 확인합니다.

체험 직원은 실제 AI를 호출하지 않습니다. 직원 등록 후 지시할 Codex 대화를 명시적으로 연결하면 [모델·강도 선택과 지시](Models.md)를 사용할 수 있습니다. 다른 공급자의 직접 실행은 지원하지 않습니다.

## 3. 기존 Codex에 지시하기

호스트에 Node.js 24.14 이상(27 미만)을 준비한 뒤 별도 터미널에서 실행합니다.

```powershell
npm ci
npm run bridge:codex -- --workspace .
```

왼쪽 **연결 설정**에서 **공개 대화 읽기**와 **Codex 지시 전송**을 켜고 저장한 뒤 적용 상태를 확인하세요. 이후 선택 변경에는 재시작이 필요 없습니다.

이 프로젝트의 최근 Codex 활동이 사무실 캐릭터와 **이 PC의 CLI 세션**에 나타납니다. 세션을 선택해 지시를 보내고 접수 상태를 확인하세요. `codex queue`를 지원하는 CLI가 필요하며 공개 응답은 대화 터미널에서 읽고 승인·중단은 원래 Codex에서 처리합니다. [연결 절차와 문제 해결](CLI.md)을 참고하세요.

## 4. 일을 마칠 때

체험 업무는 화면에서 일시 중지하거나 `docker compose stop`으로 상태를 저장합니다. 외부 Codex와 연결 프로그램은 각 터미널에서 별도로 종료합니다. 인계 파일은 내용을 검토한 후 공유하세요.

## 업무보고가 비어 있을 때

**업무보고와 답변**에는 선택한 체험 업무의 질문·결과가 표시됩니다. **질문 · 보고 목록**은 대표이사실로 이동하고, **CLI 대화 · 지시**는 실제 연결 대상 선택창을 엽니다. **대기실 · 중단 업무**에서는 보관·재연결, **연결 설정**에서는 대화 읽기·지시 전송의 적용 상태를 확인합니다. 업무가 0건이어도 이 버튼을 사용할 수 있습니다.

체험 업무를 선택해 답변을 보내면 결과 승인으로 이어집니다. 다른 업무나 방으로 이동해도 같은 브라우저 탭 안의 답변 초안은 업무별로 유지됩니다. 실제 CLI의 질문·실행 승인은 원래 CLI에서 처리하며, 사무실의 후속 지시 접수를 업무 완료로 표시하지 않습니다. [대기실와 보관 안내](Staff.md#대기실와-중단-업무).
