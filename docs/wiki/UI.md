# StackQueue Office 화면 사용법

StackQueue Office는 로컬 서버에 연결해 직원과 업무 상태를 보여줍니다. **체험용 직원**으로 질문·답변·승인 흐름을 사용할 수 있으며, 별도 연결기를 통해 이 PC의 Codex CLI 상태를 관찰할 수 있습니다. 호스트에서 명령 전송을 허용하면 기존 Codex 세션에 실제 지시를 보낼 수 있습니다. 체험용 직원의 실행은 실제 AI를 호출하지 않습니다.

사무실 이름은 서버의 `OFFICE_NAME` 환경 변수로 설정합니다. 설정된 이름은 로고 옆 제목, 작업 공간, 브라우저 제목, 사무실 표지와 하단 안내에 함께 반영됩니다.

한글은 Noto Sans KR, 영문은 JetBrains Mono를 사용합니다. 두 폰트는 앱에 포함되어 외부 폰트 서버에 접속하지 않습니다. [폰트 출처와 라이선스](../../public/fonts/README.md)를 함께 제공합니다.

## 첫 동료와 업무 시작하기

1. 오른쪽 위 **직원 채용**을 누릅니다.
2. 이름과 역할을 입력하고 체험용 공급자를 선택합니다. 모델은 `local-demo`, 추론 강도는 해당 없음으로 표시됩니다.
3. 등록된 직원의 상세 화면에서 **업무 지시**를 누르고 업무 이름과 설명을 입력합니다.
4. 직원의 고정된 안내 질문을 확인하고 답변합니다. 업무는 답변 대기에서 승인 대기로 바뀝니다.
5. 체험용 결과를 검토하고 **결과 승인**을 누르면 완료됩니다.

OpenAI, Claude, Gemini, Meta 직원도 정보 등록은 가능합니다. 아직 연결되지 않은 직원에게는 업무를 지시할 수 없으며, 확인되지 않은 모델 목록이나 추론 옵션은 표시하지 않습니다.

## 사무실과 업무 보드

- 사무실은 팀별 책상 구역, 유리 회의실, 소파 라운지와 커피 공간으로 구성합니다. 최대 여섯 캐릭터가 나타나며 연결된 CLI 세션을 먼저 배치하고 남은 자리에 등록 직원을 표시합니다. 전체 목록은 아래 직원 카드와 CLI 세션 목록에서 확인합니다. 공간 배치는 실제 부서나 업무 배정을 뜻하지 않습니다.
- 캐릭터의 타이핑은 작업 또는 활동 관찰, 손짓은 답변·승인 대기를 표현합니다. 대기 중의 가벼운 움직임은 장식이며 실제 작업 진행률을 뜻하지 않습니다. 미연결·중단·확인 필요 상태에서는 움직이지 않습니다.
- 직원이나 업무를 선택하면 역할, 연결 상태, 지원 기능, 대화와 결과를 확인할 수 있습니다. 직원 이름과 역할은 상세 화면에서 수정합니다.
- Commander의 데스크에는 답변과 승인이 필요한 업무가 표시됩니다.
- 업무 보드에서 전체, 응답·승인 대기, 미완료, 완료, 취소된 업무를 구분해 볼 수 있습니다.
- 한 직원에게는 한 번에 하나의 미완료 업무를 맡깁니다. 다른 업무를 시작하려면 기존 업무를 완료하거나 취소합니다.
- 실패, 취소, 일시 중지, 연결 끊김은 완료로 집계하지 않습니다.

화면은 약 2.5초마다 상태를 확인합니다. 서버 연결이 끊어지면 마지막 상태와 연결 오류를 표시하며 변경 작업을 막습니다. 전송 실패한 업무를 자동 재전송하지 않습니다.

## 이 PC의 CLI 세션

[CLI 상태 연결 안내](CLI.md)에 따라 연결기를 실행하면 현재 작업 공간의 Codex 세션이 별도 목록과 사무실에 나타납니다. 세션을 선택하면 마지막 이벤트 시간과 관찰 상태를 확인합니다.

- **활동 관찰**: 최근 실행 이벤트를 받았습니다. 프로세스가 계속 실행 중임을 보장하지 않습니다.
- **턴 종료 관찰**: CLI의 턴 종료 이벤트를 받았습니다. 사무실에서 지시한 업무의 완료 집계에는 포함하지 않습니다.
- **확인 필요·관찰 연결 끊김**: 최근 상태를 확인할 수 없습니다. 완료나 업무 대기로 추측하지 않습니다.

기본 연결은 상태 관찰만 허용합니다. [CLI 연결 안내](CLI.md)에 따라 호스트 연결기를 명령 허용 모드로 실행하면 세션 상세에 **지시 보내기**가 활성화됩니다. 사무실의 일시 중지·재개 버튼은 외부 CLI를 멈추거나 다시 시작하지 않습니다.

### 기존 Codex 세션에 지시하기

1. CLI 세션 카드 또는 해당 캐릭터를 선택합니다.
2. **전달할 지시**에 최대 4,000자의 내용을 입력하고 **지시 보내기**를 누릅니다.
3. 호스트 전송 대기 → Codex에 전달 중 → **Codex 큐에 접수됨** 상태를 확인합니다.
4. 기존 작업이 끝나면 큐의 지시가 실행됩니다. 답변과 결과는 원래 CLI에서 확인합니다. 지시는 해당 CLI의 기존 권한과 승인 정책을 따릅니다.

**큐에 접수됨은 작업 완료가 아닙니다.** 사무실의 완료 업무 수에도 포함하지 않습니다. 실행 중인 CLI의 강제 중단, 웹 화면으로 답변 가져오기, 새 외부 AI 직원 실행은 지원하지 않습니다.

응답을 받지 못하면 같은 지시 ID로 접수 기록만 조회하며, 자동 재전송하지 않습니다. 기록이 없을 때 표시되는 **같은 지시 다시 전송**은 기존 ID를 사용합니다. **접수 여부 확인 필요**가 표시되면 원래 CLI를 먼저 확인해 중복 지시를 피하세요. 조회 중에는 입력 내용이 잠기며, 전달 처리가 끝나면 **새 지시 작성**으로 다음 내용을 입력합니다.

같은 브라우저 탭에서 새로고침하면 지시 ID와 세션 ID로 접수 상태를 다시 조회합니다. 브라우저 저장 공간에는 이 두 ID만 보관하며 지시 원문은 저장하지 않습니다. 새로고침 전 입력한 초안과 전송 원문은 복원되지 않습니다. 복원한 ID의 접수 기록이 없다면 원래 CLI를 확인한 뒤 새 지시를 작성하세요.

사무실이 중지되었거나 호스트 연결이 끊긴 경우 새 지시를 보낼 수 없습니다. 이미 전달된 지시나 원래 CLI의 실행을 사무실 중지 버튼으로 취소할 수는 없습니다.

## 작업 중지와 인계

1. **작업 인계**에서 **사무실 일시 중지**를 누릅니다. 새 업무와 진행이 멈추고 미완료 상태가 저장됩니다.
2. **인계 기록 다운로드**를 눌러 직원과 업무의 JSON 파일을 받습니다.
3. 대화와 입력 내용이 포함되어 있으므로 파일을 공유하기 전에 내용을 확인합니다.
4. 같은 사무실의 업무를 계속하려면 **사무실 업무 재개**를 누릅니다.

인계 파일 가져오기, 다른 PC의 원래 AI 세션 복원, GitHub 자동 전송은 지원하지 않습니다. 사무실 재개는 현재 저장소에 보관된 체험 업무를 이어가는 기능입니다.

## 키보드와 작은 화면

탭 키로 탐색 메뉴, 직원 카드, 입력 항목과 버튼을 이동합니다. 첫 링크인 **본문으로 이동**으로 탐색 메뉴를 건너뛸 수 있습니다. 대화상자는 Escape 또는 닫기 버튼으로 닫습니다. 저장 요청을 처리하는 동안에는 중복 전송과 닫기를 잠시 막습니다.

작은 화면에서는 탐색 메뉴가 위쪽으로 이동하고 카드가 세로로 배치됩니다. 이름·상태·버튼은 읽기 쉬운 한 줄을 유지합니다. 긴 이름은 카드에서 말줄임으로 표시하며, 선택하면 상세 화면에서 전체 이름을 확인할 수 있습니다. 설명과 대화는 화면 폭에 맞춰 자연스럽게 줄바꿈됩니다. 아래쪽 프로그램 카드의 GitHub 링크는 새 탭에서 열립니다.

사무실의 **움직임 켜짐/꺼짐** 버튼으로 캐릭터 애니메이션을 바꿀 수 있습니다. 운영체제나 브라우저에서 동작 줄이기를 사용하면 애니메이션을 재생하지 않습니다. 이름과 상태는 움직임 없이도 확인할 수 있습니다. StackQueue Blog 카드는 지정된 네이버 블로그를 새 탭에서 엽니다.

## 문제 해결

- **서버 연결 끊김**: 로컬 서버 실행 상태와 접속 주소를 확인하고 **다시 연결**을 누릅니다.
- **업무 지시가 비활성화됨**: 체험용 직원인지, 진행 중 업무가 있는지, 사무실이 중지되었는지 확인합니다.
- **답변을 입력할 수 없음**: 업무가 답변 대기인지 확인합니다. 승인 대기에는 결과 승인 버튼이 표시됩니다.
- **CLI 지시를 보낼 수 없음**: 사무실 중지 여부와 호스트의 명령 허용 설정을 확인합니다. 세션 상세에 전송 불가 사유가 표시됩니다.
- **새로고침 후 입력 내용이 사라짐**: 전송하지 않은 입력은 저장되지 않습니다. 전송된 대화와 직원 정보는 서버에 보관됩니다.

## 개발 검증

화면은 `public/index.html`, `public/styles.css`, `public/app.js`로 구성하고, 상태 판정과 요청 처리는 `public/model.mjs`, `public/api.mjs`에서 관리합니다. `public/commands.mjs`는 실제 CLI 지시의 접수 조회와 동일 ID 재시도를 담당합니다. 자체 제작 사무실 도형은 `public/office.svg`, 폰트와 라이선스는 `public/fonts/`에 있습니다. 외부 UI 라이브러리와 빌드 단계는 필요하지 않습니다.

상태 판정, 실행 가능 조건, 입력 문자열 처리, 프로그램 링크 제한, 네트워크 오류와 중복 재시도 방지는 `tests/ui/*.test.mjs`에서 검증합니다. 명령 테스트는 응답 유실, 동일 ID 재전송, 조회 실패, 중복 클릭, 권한·연결·사무실 중지 조건을 확인합니다.

```sh
node --test tests/ui/*.test.mjs
```
