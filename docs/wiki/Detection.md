# CLI와 AI 웹 탭 감지

사무실의 **직원 · 연결 관리 → 연결 관리 → 감지** 탭에서 로컬 CLI와 브라우저에서 열린 AI 탭을 함께 확인합니다. 종류·공급자 필터를 사용할 수 있습니다. 같은 패널의 **연결 점검** 탭으로 전환하면 대상별 진단 결과가 표시됩니다. 탭을 바꿔도 필터와 감지 갱신은 유지됩니다.

항목의 **직원 등록·연결**에서 새 직원을 만들거나 같은 공급자의 기존 직원에 연결하세요. 등록된 항목은 직원 보기로 바뀝니다. 웹은 관찰 전용이며 실제 지시 가능 여부는 연결 방식에 따릅니다. [직원 등록·재연결 안내](Staff.md)를 참고하세요.

탭에 키보드 초점을 두고 좌우 방향키 또는 Home·End로 전환할 수 있습니다.

## 표시되는 대상

| 대상 | 감지 방법과 의미 |
| --- | --- |
| CLI 프로세스 | Windows 로그인 세션 또는 Linux 같은 사용자의 지원 프로세스 추가·종료를 확인합니다. 프로세스와 저장된 대화는 별도로 표시합니다. |
| Codex CLI 기록 | 선택한 프로젝트의 최근 기록을 표시합니다. 기록이 있다고 현재 프로세스가 실행 중인 것은 아닙니다. |
| ChatGPT·Claude·Gemini·Meta AI 웹 | Windows·Linux의 Chrome/Chromium 확장프로그램을 연결한 프로필의 여러 창에서 열린 탭을 확인합니다. |

식별 가능한 대화 주소는 **대화 탭**, 홈페이지·새 채팅·로그인·기타 화면은 **서비스·새 대화 화면**으로 표시합니다. 같은 대화를 여러 탭에서 열면 한 항목과 탭 수로 묶습니다. 다른 브라우저 프로필은 별도 연결로 표시합니다. 서로 다른 계정이나 CLI·웹이 같은 세션이라고 추정하지 않습니다.

**탭 열림**은 로그인 성공·답변 생성·업무 완료를 의미하지 않습니다. 웹 감지는 대화 읽기나 메시지 전송 기능을 제공하지 않습니다. 현재 Codex 지시는 기존 [CLI 연결](CLI.md)에서 지원 범위를 확인하세요.

## Chrome 확장프로그램 연결

확장프로그램 소스는 저장소의 `extensions/browser-observer/`에 있습니다. Chrome 120 이상을 대상으로 하며 별도 npm 설치나 빌드가 필요 없습니다.

Linux에서도 같은 확장을 설치합니다. Docker 실행만으로 브라우저 확장이 설치되지는 않습니다. CLI 연결 프로그램은 Docker 호스트에서, 확장은 실제 AI 탭을 여는 브라우저 프로필에서 실행하세요. [Linux 실행 안내](Linux.md).

1. 로컬 사무실을 실행합니다. 기본 주소는 `http://localhost:8080`입니다.
2. Chrome에서 `chrome://extensions`를 열고 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**에서 저장소의 `extensions/browser-observer` 폴더를 선택합니다.
4. 사무실 페이지를 새로고침합니다. **연결 관리 → 감지 → 웹 탭 감지 켜기**를 누릅니다.
5. 지원 사이트를 열고 **감지 새로고침**을 누릅니다. 이후 사무실 페이지가 열려 있는 동안 약 15초마다 갱신합니다. 백그라운드 탭은 브라우저 정책에 따라 늦어질 수 있습니다.

기본 전달 대상은 로컬 8080 포트입니다. 다른 포트를 쓰면 확장프로그램 아이콘을 눌러 **사무실 주소**를 변경하세요. 설정한 포트의 localhost·127.0.0.1만 허용하며 다른 로컬 서비스로는 전달하지 않습니다.

확장프로그램은 ChatGPT·Claude·Gemini·Meta AI 도메인의 탭 URL을 확인할 수 있는 권한과 로컬 사무실에 연결하는 콘텐츠 스크립트를 사용합니다. 전체 사이트 접근, `tabs`, 쿠키, 방문 기록, 화면 캡처 권한을 요청하지 않습니다. 0.2.0부터 AI 페이지에는 개별 선택을 검사하는 검색 보관 스크립트도 준비됩니다. 기본 감지만으로 본문을 읽지 않으며 사용자가 선택한 대화의 [검색 보관](Search.md)을 별도로 켜야 동작합니다.

전달하는 데이터는 공급자, 탭 구분, 익명화한 대화 식별자, 무작위 브라우저 별칭, 확인 시각뿐입니다. 대화 제목·본문·검색어·URL 쿼리·계정 정보는 전달하지 않습니다. 시크릿 탭도 제외합니다. 감지 결과는 로컬 서버 메모리에서만 보관하며 서버를 재시작하면 다시 감지합니다.

## CLI 연결

프로젝트 폴더에서 다음 명령으로 기존 Codex 관찰을 연결합니다.

```powershell
npm run bridge:codex -- --workspace .
```

지시 전송이 필요하면 **연결 설정 → Codex 지시 전송**을 켜고 저장합니다. 웹 감지를 켜도 CLI 명령 권한은 바뀌지 않습니다. CLI 설정과 지원 플랫폼은 [CLI 안내](CLI.md)를 따릅니다.

## 연결 끊기와 문제 해결

- **웹 탭 감지 끄기**: 이 사무실 주소에서 열린 페이지들의 감지를 중지하고 해당 브라우저의 서버 관찰값을 지웁니다. 탭이나 대화는 닫지 않습니다. 다른 프로필은 별도로 끕니다.
- **확장프로그램 응답 없음**: 설치·활성화 여부와 프로필을 확인하고 사무실 페이지를 새로고침합니다. 확장프로그램 업데이트 후에도 새로고침이 필요합니다.
- **탭 0개**: 연결은 정상이나 그 프로필에 지원 사이트 탭이 없습니다. 다른 프로필·시크릿 창은 감지하지 않습니다.
- **감지 연결 끊김**: 90초 동안 최신 관찰이 없습니다. 이전 항목은 마지막 수신 상태로 남고 열린 탭 수에 포함하지 않습니다. 한 시간 동안 갱신되지 않은 연결은 메모리에서 제거합니다.
- **탭 닫기·다른 사이트로 이동**: 다음 정상 감지에서 목록과 집계에서 빠집니다. 연결 끊김을 탭 닫힘으로 추정하지 않습니다.
- **수집 한도**: 프로필당 128개 탭, 서버당 8개 프로필입니다. 한도를 넘으면 일부만 표시됨을 안내합니다.
- **확장프로그램 제거**: 먼저 감지를 끄고 `chrome://extensions`에서 **StackQueue 웹 탭 감지 → 삭제**를 선택합니다.

사무실 URL은 `http://localhost:<포트>/` 또는 `http://127.0.0.1:<포트>/`를 사용하세요. 외부 서버나 다른 경로로는 전달하지 않습니다. 두 주소는 별도 브라우저 저장소를 사용하므로 감지 켜기·끄기를 각각 적용합니다.

## 검증 범위

자동 검증은 네 공급자의 복수 탭·동일 대화 중복·탭 닫기·허용 도메인·새 대화·연결 중단과 복구·프로필 분리·원문 제외·HTTP origin 검증·인계 제외를 확인합니다. 실제 Chrome 설치와 실시간 표시 결과는 [검증 기록](https://github.com/parkhw328/wook-home/blob/main/docs/validation.md)에 별도로 기록합니다.

설계 근거: [Chrome 탭 API와 사이트 권한](https://developer.chrome.com/docs/extensions/reference/api/tabs), [로컬 페이지 콘텐츠 스크립트](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts).
