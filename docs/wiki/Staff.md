# CLI·웹을 직원으로 등록하기

**직원 · 연결 관리**를 펼치면 직원 목록과 **연결 관리 → 감지 / 연결 점검**을 한곳에서 사용할 수 있습니다.

## 감지에서 등록

1. [CLI 연결](CLI.md) 또는 [웹 감지](Detection.md)를 준비합니다. 웹은 연결한 Chrome 프로필의 지원 사이트만 표시합니다.
2. **감지** 탭에서 종류·공급자 필터로 대상을 찾고 **직원 등록·연결**을 누릅니다.
3. **새 직원 등록**을 선택해 이름·역할을 입력하거나, 같은 공급자의 **기존 직원**을 선택합니다. 공급자는 감지 대상에 맞춰 지정됩니다.
4. 등록한 직원의 상세에서 연결 상태와 가능한 작업을 확인합니다. 같은 감지 대상은 한 직원에만 연결하며, 등록 후에는 **직원 이름 보기**로 표시합니다.

상단 **직원 채용 → 감지한 CLI·웹으로 등록**에서도 시작할 수 있습니다. 체험 직원과 연결 없는 직원 정보 등록은 기존 채용 양식으로 진행합니다.

## 연결별 가능한 작업

| 연결 | 가능한 작업 |
| --- | --- |
| Codex CLI 대화 기록 | 관찰, 설정된 공개 대화 보기, 호스트가 명시적으로 허용한 경우 **CLI 지시 보내기** |
| CLI 실행 프로세스 | 실행·종료 관찰. 대화 연결이 확인되지 않아 지시 전송 불가 |
| 웹 대화 탭 | 열림·닫힘 관찰과 공식 서비스 열기. 메시지는 원래 웹 서비스에서 작성 |
| 웹 서비스·새 대화 화면 | 해당 화면의 열림 관찰. 로그인이나 진행 중인 대화가 확인된 상태가 아님 |

등록 자체로 모델 변경·웹 대화 수집·웹 지시·새 AI 실행 권한이 생기지 않습니다. 같은 계정의 CLI와 웹을 같은 세션으로 합치지 않습니다. 여러 탭에서 같은 웹 대화를 열었다면 한 직원에 탭 수를 함께 표시합니다.

## 변경·해제·다시 연결

- 직원 상세의 **연결 변경·다시 연결**에서 같은 공급자의 다른 감지 대상을 선택합니다. 기존 직원에 연결하면 원래 연결이 교체됩니다.
- **연결 해제**는 직원 정보와 원래 CLI·탭을 그대로 두고 사무실 연결만 해제합니다.
- 탭 닫힘·프로세스 종료와 감지 연결 끊김은 구분하며 직원 정보는 유지됩니다. 새로운 대화 주소는 별도 대상이므로 필요하면 직접 다시 연결하세요.
- 서버·Docker를 재시작하면 **다시 연결 필요**로 표시합니다. 직원 이름·역할·공급자는 저장하지만 감지 식별자와 연결 매핑은 메모리에만 보관하므로 기존 직원을 선택해 재연결합니다.
- 연결이 이미 사용 중이거나 등록 도중 사라졌다면 최신 목록을 확인하세요. 중복 클릭으로 직원을 추가하지 않습니다.

웹 감지 제목·본문·쿠키·로그인 정보를 수집하지 않으며 관찰 정보와 연결 매핑을 Git·배포물·인계 JSON에 포함하지 않습니다. 전체 대상의 상태 진단은 같은 패널의 [연결 점검](Connections.md)을 이용하세요.
