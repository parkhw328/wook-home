# CLI·웹을 직원으로 등록하기

**직원 · 연결 관리**를 펼치면 직원 목록과 **연결 관리 → 감지 / 연결 점검**을 한곳에서 사용할 수 있습니다.

## 살아 있는 세션과 별칭

연결된 Codex에서 살아 있는 세션은 프로젝트별로 직원으로 자동 등록되고 각 프로젝트의 전용 층에 배치됩니다. 기본 화면에는 별칭과 작은 **ID** 표시를 두고, 카드에 마우스를 올리면 **session-id** 전체가 나타납니다. 키보드로 카드·ID 버튼에 초점을 맞춰도 확인할 수 있습니다. 모바일에서는 상세창이나 등록창의 **ID** 버튼을 누르세요. 툴팁의 전체 ID를 선택해 복사할 수 있으며 Escape나 바깥 선택으로 닫습니다. 같은 앞·뒤 글자를 가진 여러 세션도 전체 ID로 구별할 수 있습니다. **별칭 · 직원 설정**에서 부를 이름을 저장하세요. 별칭이 같아도 세션은 합쳐지지 않습니다.

생존이 확인되지 않은 기록은 **미등록 세션 · 등록 대기**에, 웹·프로세스는 **감지 → 미등록 감지 대상**에 표시합니다. 이 목록은 직원 수·캐릭터에 포함하지 않습니다. 아래 절차로 직접 등록하거나 기존 직원에 연결할 수 있습니다. 등록하면 대기 목록에서 빠집니다. 실제 session-id가 없는 항목의 ID 툴팁에는 **감지 ID · session-id 미확인**과 전체 감지 식별자를 표시합니다. 등록 선택란에는 목록 번호와 이름이 표시되며 선택 후 **ID** 버튼에서 정확한 대상을 확인하세요.

이미 켜 둔 호스트 연결기는 최신 코드로 한 번 다시 실행해야 생존 확인을 전달합니다. 자동 등록은 연결된 Codex의 실제 적재 세션과 세션별 작업 폴더 메타데이터를 대조하며, 단순한 프로세스 수나 최근 대화 기록으로 추정하지 않습니다. 적재 확인을 지원하지 않거나 연결이 끊겼다면 수동 등록을 사용하세요.

## 감지에서 등록

1. [CLI 연결](CLI.md) 또는 [웹 감지](Detection.md)를 준비합니다. 웹은 연결한 Chrome 프로필의 지원 사이트만 표시합니다.
2. **감지** 탭에서 종류·공급자 필터로 대상을 찾고 **직원 등록·연결**을 누릅니다.
3. **새 직원 등록**을 선택해 별칭·역할과 선택 사항인 담당 프로젝트를 입력하거나, 같은 공급자의 **기존 직원**을 선택합니다. 공급자는 감지 대상에 맞춰 지정됩니다.
4. 등록한 직원의 상세에서 연결 상태와 가능한 작업을 확인합니다. 같은 감지 대상은 한 직원에만 연결하며, 등록 후에는 **직원 이름 보기**로 표시합니다.

상단 **직원 채용 → 감지한 CLI·웹으로 등록**에서도 시작할 수 있습니다. 체험 직원과 연결 없는 직원 정보 등록은 기존 채용 양식으로 진행합니다.

## 연결별 가능한 작업

| 연결 | 가능한 작업 |
| --- | --- |
| Codex CLI 대화 기록 | 관찰, 설정된 공개 대화 보기, 호스트가 명시적으로 허용한 경우 **모델·추론 강도 선택과 작업 지시** |
| CLI 실행 프로세스 | 실행·종료 관찰. 대화 연결이 확인되지 않아 지시 전송 불가 |
| 웹 대화 탭 | 열림·닫힘 관찰과 공식 서비스 열기. 메시지는 원래 웹 서비스에서 작성 |
| 웹 서비스·새 대화 화면 | 해당 화면의 열림 관찰. 로그인이나 진행 중인 대화가 확인된 상태가 아님 |

등록 자체로 모델 변경·웹 대화 수집·웹 지시·새 AI 실행 권한이 생기지 않습니다. 같은 계정의 CLI와 웹을 같은 세션으로 합치지 않습니다. 여러 탭에서 같은 웹 대화를 열었다면 한 직원에 탭 수를 함께 표시합니다.

## 담당 프로젝트와 기본 추론 설정

직원 목록의 **별칭 · 직원 설정** 또는 직원 상세의 같은 버튼을 누릅니다. 담당 프로젝트 이름을 입력하거나 기존 이름을 선택하고 **변경 사항 저장**을 누르세요. 한 직원의 대표 담당 프로젝트를 지정하며, 입력을 비우면 배정을 해제합니다. 채용할 때에도 입력할 수 있습니다.

목록·방 안 직원·현황 상세에서 담당 프로젝트를 확인합니다. 배정 전이라도 연결된 CLI 대화의 프로젝트가 확인되면 **CLI 작업 · 프로젝트 (배정 미지정)**으로 표시합니다. 상세에서는 담당 프로젝트와 **CLI 작업 프로젝트**를 각각 보여 줍니다. 웹 탭이나 실행 프로세스로 프로젝트를 추정하지 않습니다. 배정을 바꾸어도 기존 CLI의 작업 폴더는 바뀌지 않습니다. 다른 폴더에서 실행하려면 그 프로젝트의 대화를 명시적으로 연결하세요.

지원되는 Codex 직원은 같은 설정 화면에서 기본 모델·강도를 저장할 수 있습니다. 직원별 선택은 로컬 DB에 남으며 새로고침·서버 재시작 후에도 유지됩니다. 저장만으로 지시를 전송하지 않고, 다음 지시 화면에서 기본 선택으로 사용합니다. 개별 지시에서 직접 고른 선택이 있으면 그 초안의 선택을 유지합니다. 실제 모델 변경은 지시를 보낼 때 확인합니다.

다른 창에서 설정이나 연결을 바꾸면 충돌 안내와 함께 작성 내용을 유지합니다. **최신 설정 다시 불러오기**는 미저장 초안을 현재 저장값으로 바꾸므로 필요한 초안을 확인한 후 누르세요. 지원하지 않는 공급자의 모델 제어는 제공하지 않습니다.

## 모델과 작업 지시

직원 상세의 **모델 설정과 작업 지시**에서 모델·추론 강도를 고르고 할 일을 입력합니다. 모델 목록은 실제 Codex 연결에서 가져오며, 선택은 지시 전송 시 다음 실행의 기본값으로 적용합니다. **현재 CLI 설정 유지**도 선택할 수 있습니다. 대화 모달에서는 **직원 정보**로 이동하세요.

OpenAI 직원이 프로세스·웹 관찰 또는 미연결 상태이면 **지시할 Codex 대화 연결**을 눌러 현재 프로젝트의 대화를 명시적으로 선택합니다. 지시 전송이 꺼졌다면 **연결 설정 열기**, 사무실이 중지되었다면 **사무실 업무 재개**를 사용하세요. [모델 선택·적용과 오류 안내](Models.md).

## 변경·해제·다시 연결

- 직원 상세의 **연결 변경·다시 연결**에서 같은 공급자의 다른 감지 대상을 선택합니다. 기존 직원에 연결하면 원래 연결이 교체됩니다.
- **연결 해제**는 직원 정보와 원래 CLI·탭을 그대로 두고 사무실 연결만 해제합니다.
- 탭 닫힘·프로세스 종료와 감지 연결 끊김은 구분하며 직원 정보는 유지됩니다. 새로운 대화 주소는 별도 대상이므로 필요하면 직접 다시 연결하세요.
- 서버·Docker를 재시작해도 별칭과 설정은 유지합니다. 생존이 확인된 같은 Codex 세션은 기존 직원으로 자동 연결합니다. 웹·프로세스·생존 미확인 세션은 **다시 연결 필요**로 남으며 직접 선택합니다. 이전 버전에서 등록한 세션 직원은 최초 한 번 현재 대상을 다시 연결하세요.
- 연결이 이미 사용 중이거나 등록 도중 사라졌다면 최신 목록을 확인하세요. 중복 클릭으로 직원을 추가하지 않습니다.

웹 감지 제목·본문·쿠키·로그인 정보를 수집하지 않으며 관찰 정보와 연결 매핑을 Git·배포물·인계 JSON에 포함하지 않습니다. 전체 대상의 상태 진단은 같은 패널의 [연결 점검](Connections.md)을 이용하세요.

## 대기실와 중단 업무

1층 **대기실**에서 보관 업무와 연결 확인이 필요한 직원·CLI를 확인합니다. **대기실 보관 중**은 사용자가 보관한 업무이며 **연결 확인 필요 · 아직 보관하지 않음**은 관찰 연결이 사라진 항목입니다. 감지 연결 끊김을 실제 CLI 종료·업무 완료로 판정하지 않습니다.

1. CLI 대화창의 **업무 보관**, 직원 상세의 **보관 · 복귀 · 메모**, 또는 대기실의 **보관할 업무 선택**을 누릅니다.
2. 담당 프로젝트와 완료한 일·남은 일·다음 행동을 적고 **대기실에 보관 · 메모 저장**을 누릅니다. 미등록 CLI 기록은 직원 업무로 등록됩니다.
3. 대기실에서 메모를 열고 수정합니다. **메모 저장 · 사무실로 복귀**를 누르면 보관 표시를 해제합니다.
4. 직원 상세의 **연결 변경·다시 연결**에서 같은 공급자의 현재 감지 대상을 직접 선택합니다. 복귀 후에도 연결이 없으면 대기실에 연결 확인 대상으로 남습니다.
5. 연결·지원 기능을 확인하고 새 지시를 직접 작성합니다. 보관·복귀·재연결은 실제 프로세스 종료나 세션 복원, 이전 지시 재전송을 하지 않습니다. 원래 CLI의 질문 답변·실행 승인은 원래 CLI에서 처리합니다.

직원과 보관 메모는 서버 재시작 후에도 유지됩니다. 메모는 최대 4,000자이며 이 PC의 로컬 DB에만 보관하고 인계 내보내기에서 제외합니다. 원문 관찰 식별자는 저장하지 않습니다. 로컬 해시 등록 기록으로 같은 살아 있는 Codex 세션의 직원 별칭을 복원하며 그 밖의 연결은 직접 선택합니다. 이미 검색 보관한 대화는 **이전 대화 검색**에서 확인하세요. 목록에서 사라지기 전에 등록·보관하지 않은 세션의 본문을 대기실가 자동 복원하지는 않습니다.

다른 화면에서 설정을 변경해 저장이 충돌하면 초안이 남습니다. **충돌 시 최신 버전 확인 · 메모 유지**를 누르고 내용을 검토한 뒤 저장하세요. 체험 직원의 질문·승인·취소는 기존 업무보고에서 관리합니다.

## 직원 등록 해제와 다시 등록

직원 상세의 **직원 등록 해제**를 누르고 대상과 보존 안내를 확인한 뒤 해제합니다. CLI 대화창으로 열리는 직원은 **직원 정보**를 눌러 상세로 이동하세요. **연결 해제**는 직원 명단을 유지하고 연결만 풀며, **직원 등록 해제**는 명단·직원 수·캐릭터에서도 제외합니다. 실제 CLI나 웹 탭은 종료하지 않으므로 계속 감지되는 CLI는 미등록 세션으로 돌아갑니다. 연결 해제·변경·직원 해제 후에는 자동으로 재등록하지 않으며, 다시 등록하려면 직접 선택하세요.

- 진행 중이거나 일시중지된 체험 업무가 있으면 먼저 완료하거나 취소해야 합니다. 해제 화면에서 해당 업무를 열 수 있습니다.
- 기존 완료·취소·실패 업무와 작성한 보관 메모는 유지합니다. **직원 · 연결 관리 → 직원 등록 해제 기록**에서 확인하거나 대기실·업무 연결 선택창에서 같은 기록을 열 수 있습니다.
- 해제 기록에서 **직원으로 다시 등록**을 누르면 같은 직원 정보와 메모를 복원합니다. 외부 연결은 현재 감지 목록에서 다시 선택합니다. 새 AI 실행·이전 지시 재전송은 하지 않습니다.
- 서버를 재시작해도 해제 상태와 기록은 유지됩니다. 동시에 설정이 변경된 경우 최신 상세를 다시 확인하고 해제하세요.

살아 있는 등록 직원은 턴 종료 후에도 사무실에 남습니다. 연결 소실·생존 미확인 직원과 직접 보관한 업무는 1층 대기실에서 구분하고, 미등록 세션은 등록 대기 목록에 둡니다. 사무실 목록과 캐릭터는 같은 배치 기준을 사용합니다. 이는 실제 CLI 종료 판정이나 자동 업무 보관이 아니며, 대화 확인·새 지시·명시적 보관은 계속 이용할 수 있습니다. 유효한 질문·승인 요청과 최근 협업은 해당 공간에 표시합니다.
