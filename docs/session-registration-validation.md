# 세션 직원 등록 검증 — 2026-10-27

## 적용 기준

FR-64~67에 따라 현재 프로젝트의 살아 있는 Codex 세션은 직원으로 등록하고 전체 session-id와 수정 가능한 별칭을 함께 표시한다. 미등록 기록·웹·프로세스는 별도 등록 대기 목록에 두고 직원 수와 캐릭터에서 제외한다. 살아 있는 등록 직원은 턴 종료 후에도 사무실에 남는다.

현재 적재 여부는 [공식 Codex App Server](https://learn.chatgpt.com/docs/app-server#list-loaded-threads)의 `thread/loaded/list`로 확인한다. `thread/read`는 `includeTurns: false`로 요청해 정확한 작업 폴더만 비교한다. 다른 프로젝트의 ID·미리보기·경로와 대화 원문을 상태 파일이나 검증 산출물에 기록하지 않는다. 설치된 CLI 0.164.0의 생성 스키마와 실제 읽기 전용 응답을 확인했다. 새 작업·세션 재개·모델 변경·지시 전송은 실행하지 않았다.

## 자동 검증

- `npm test`: 서버·UI·확장 235개 통과. 같은 앞·뒤 글자와 같은 별칭을 가진 세 세션의 독립 등록, 반복 조회·서버 재생성 후 중복 방지와 별칭 보존을 포함한다.
- 생존 미확인·현재 적재되지 않음·끊김·프로세스 수만 있는 경우의 자동 등록 금지, 직원 한도, 해제·연결 변경 후 자동 등록 제외, 명시적 재연결을 확인했다.
- 공개 상태와 인계에 로컬 해시 레지스트리가 없고 로컬 DB에 원문 세션 ID가 없는지 검사했다. 보관 메모와 직원 정보 유지, 버전 충돌 시 등록 선택 보존도 검사했다.
- 실제 WebSocket 모의 서버로 적재 목록 페이지 전환·잘못된 응답·부분 실패·반복 커서·메타데이터의 프로젝트 격리를 확인했다. 지시·재개·본문 수집 요청이 없는지도 검사했다.
- 생존 근거가 사라지면 최근 협업 이벤트가 남아도 직원의 회의·발표 동작을 해제하는 UI 회귀 10개도 통과했다.

## 브라우저 검증

`tests/browser/session-registration-preview.mjs`의 격리 메모리 DB와 합성 세션으로 검증했다. 실제 직원·사용자 업무 데이터에 테스트를 실행하지 않았다.

- 라이트·다크 각각 320·390·768·1366·1920px, Chromium 실제 브라우저 200% 확대.
- 자동 등록 세 명과 미등록 두 개의 분리, 별칭 저장·새로고침 복원, 전체 ID로 세션 구별, 직원·방 목록·대화·연결·설정 화면의 ID 표시.
- 새 직원 등록 후 대기 목록에서 제거, 해제 후 대기 목록으로 복귀, 연결 양식 새로고침 뒤 별칭·대상 보존, 기존 직원 선택에서도 전체 ID 확인.
- 전체 ID로 길어진 맵 이름표도 320px·1366px에서 세 명의 경계·겹침을 검사했다. 가까운 앵커의 탐색 간격 때문에 빈 공간을 놓치던 배치도 수정하고 자동 회귀에 포함했다.
- ID의 최종 글꼴 14px 이상, 조작 글꼴 16px·높이 44px 이상, 320px 가로 넘침·ID 잘림 없음. 화면과 결과는 Git 제외 `artifacts/session-registration/`에 남긴다.

## 한계와 복원

자동 등록은 연결한 Codex 엔드포인트와 선택한 프로젝트 범위다. 같은 PC의 모든 프로세스나 계정 전체가 대상인 것은 아니다. 다른 공급자와 웹·프로세스는 수동 등록한다. 새 연결기 코드가 적용되어야 생존 정보를 전달한다. 기존 버전의 세션 직원은 최초 한 번 명시적으로 연결하며 이름으로 정체성을 추정하지 않는다.

등록 관찰과 공개 대화 읽기는 별개다. 새 형식의 세션도 등록하지만 공개 대화는 기존 기록 수집 범위에 따르며 없는 기록을 생성하지 않는다. 적재 목록 조회 실패는 생존 확인 불가로 표시하고 실제 프로세스 종료로 판정하지 않는다.

직원과 해제 선택은 로컬 DB에 유지하며 세션 원문 ID는 저장하지 않는다. 재시작 후 실제로 살아 있는 같은 세션만 기존 별칭으로 연결한다. 등록 해제한 대상은 직접 등록·연결해야 돌아온다. 배포 확인은 실행 환경 기록과 구분한다.
