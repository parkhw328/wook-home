# 현황 상세와 탐색 영역 검증

검증일: 2026-10-22. 변경 전 기준은 `a257365`이며, 동시에 진행 중인 테마 작업과 분리한 소스 사본으로 검증했다.

## 자동 검증

- Node.js 26.8.1에서 `npm test`: **150개 통과**.
- 현황 숫자와 목록의 동일한 상태 분류, 답변/승인→완료 전환, 실패·취소·일시 중지 제외, 미등록 CLI 제외, 정렬과 원본 배열 보존을 확인했다.
- 방 이동 중 선택한 업무는 대기 중인 이동이 끝난 뒤 준비된다. 다른 목적지로 선택을 바꾼 경우 앞선 호출도 종료되고 마지막 선택만 반영되는지 검증했다.

## 브라우저 검증

Python Playwright와 Chromium 151에서 별도의 메모리 DB 서버와 브라우저 전용 검증 데이터를 사용했다. 실제 사무실 DB에 검증용 직원·업무를 저장하지 않았다.

- 다섯 방에서 네 현황 카드를 열어 직원 18명, 진행 5건, 응답·승인 2건, 완료 1건의 목록과 집계 일치를 확인했다.
- 직원 선택→역할·연결·업무 상세, 완료 업무 선택→해당 방의 보고·결과·대화와 화면 이동을 확인했다.
- 일반 애니메이션으로 방을 이동하는 중에도 현황→업무를 선택하면 이동 완료 뒤 업무보고에 초점이 놓이고 화면에 나타난다.
- 자동 갱신 중 목록 스크롤·항목 초점 유지, 상태 변경 후 0건 안내, 서버 연결 끊김의 마지막 수신 목록과 복구를 확인했다.
- 빠른 반복 열기·닫기, Enter로 열기, Escape로 닫기와 원래 현황 카드로의 초점 복귀를 확인했다. 이전 닫기 이벤트가 다시 열린 목록의 상태를 지우지 않는다.
- 직원 이름의 HTML 형태 문자열은 텍스트로만 표시되고 요소나 스크립트로 실행되지 않았다.
- 320·390·768·1366·1920px에서 가로 넘침, 대화상자 잘림, 층 안내 헤더의 한 줄 배치와 사용자/도움말 구역 분리를 확인했다. 제목은 22px, 현황 카드 글씨는 16px, 버전·보조 정보는 최소 14px를 유지했다.
- 임시 브라우저 프로필의 실제 200% 탭 확대에서 상세 목록 열기·읽기·닫기·초점 복귀와 가로 넘침 없음을 확인했다.
- 전체화면 안에서도 목록이 열리고 닫은 뒤 전체화면과 원래 현황 카드의 초점이 유지된다. 브라우저 JavaScript 오류는 없었다.

## 집계 범위

방 안의 네 현황 카드는 사무실 전체 집계이며 현재 방의 실제 인원수는 장면의 방 이름 옆에 표시한다. 진행 업무에는 접수·실행·답변 대기·승인 대기가 포함된다. 현황 열람은 외부 CLI 실행이나 업무 상태를 변경하지 않는다.

## 배포 확인

검증한 소스 사본으로 Docker 이미지를 다시 빌드해 기존 Compose 서비스에 반영했다. `0.0.0.0:8080` 바인딩과 설정된 Host 허용 목록을 유지하고 컨테이너 healthy, HTTP 상태 확인, 실제 화면의 현황 모달·닫기·초점 복귀·사용자/도움말 구역을 검증했다. 실제 AI 호출이나 새 직원·업무 생성은 수행하지 않았다.
