# 로컬 버전 검증 기록

대상: 0.1.0-dev. 초기 체험 업무부터 이후 기능까지 누적한 검증 기록이다. 아래의 이전 화면 검증은 이후 다층 입체 사무실 요구사항의 완료 근거가 아니다.

## 다층 입체 사무실 — 2026-10-22

- Three.js 0.186.1로 건물의 층판·유리벽·문·엘리베이터·가구와 인물의 입체 지오메트리를 구성했다. 1층 휴게실·다과실, 2층 사무실, 3층 회의실·대표이사실의 전체 보기와 층별 확대를 Chrome WebGL 2에서 확인했다. 평면도 자산은 제거했다.
- 방과 각 층 복도 사이의 모든 경로에서 문을 거치고, 수직 이동은 층판이 없는 엘리베이터 위치에서만 일어나는지 자동 검증했다. 퇴실은 같은 층 복도로 연결된다. 렌더가 정지된 탭에서도 입장 완료가 무한 대기하지 않는 회귀 검증을 추가했다.
- 별도 검증 환경에서 2층 사무실 업무 지시 → 3층 회의실 답변 → 대표이사실 결과 승인·완료를 확인했다. 1층 직원, 2층 CLI 캐릭터의 배치·보행과 업무 상태에 따른 공간 이동을 확인했다. 보행 자체는 업무 실행 이벤트로 기록하지 않는다.
- Chrome 320·390·768·1366px에서 페이지 가로 넘침 없이 모든 층·방 선택 버튼에 접근하고 입체 장면을 렌더했다. 동작 줄이기에서 즉시 입장하고 Escape로 같은 층 복도에 퇴실하는 것을 확인했다. WebGL 생성 실패 시에도 방 탐색·입장이 유지되는 자동 검증을 추가했다.
- 검증된 기본 코드와 이 변경 파일만 포함한 별도 트리에서 전체 테스트 **99개 통과**. 그 트리로 Docker 이미지를 빌드·교체하고 기본 8080의 실제 CLI 저장 세션 5개, 대화기록·지시 전송 연결, 사무실 재개와 입체 렌더를 확인했다. 다른 기능의 개발 중 파일은 이 이미지에 포함하지 않았다.
- Three.js 모듈과 MIT 라이선스는 버전·무결성을 고정한 npm 패키지에서 복사하고 로컬에서 제공한다. 이미지에 이전 평면도, 로컬 참고 자료, 인증 설정, Git과 호스트 연결 프로그램이 없음을 확인했다.

## 한글·영문 가독성 — 2026-10-22

- 기존 안정 버전과 가독성 변경만 포함한 별도 환경에서 `npm test` 96개가 통과했다. 동시 개발 중인 다층 사무실과 새 직원 연결 변경은 이 검증 범위에 포함하지 않았다.
- Chrome 320·390·768·1366·1920px에서 공통 글자 크기를 확인했다. 표시된 읽기용 텍스트 중 14px 미만은 없고 페이지 가로 넘침이 없었다. 닫힌 패널의 내용은 표시 영역 검사에서 제외했다.
- 320px에서 채용 입력·선택 16px, 업무 보드·인계·감지·연결 점검 탭, 긴 직원 이름과 역할 줄바꿈을 확인했다. 보고 본문·대화는 17px, 역할·시각·버전·영문 소제목은 14px이며 버튼은 16px 이상이다. 브라우저 오류·경고는 없었다.
- 960×450px에서는 고정 사이드바의 세로 스크롤과 메뉴 접근을 확인했다. 이는 실제 브라우저 확대 검증을 대신하지 않는다. 현재 브라우저 자동화 도구가 데스크톱 확대율 조절을 제공하지 않아 200% 실제 확대 검증은 남아 있다.

## 공간별 업무·대화·감지 통합 — 2026-10-22

- 전체 `npm test` 96개 통과, `git diff --check`와 Compose 구성 검사 통과. 기본 Docker를 다시 빌드하고 8080 health check, 사무실 재개, 기존 CLI 지시 전송과 대화기록 연결을 확인했다. 이미지에는 서버·공개 자산만 포함하고 로컬 참고 자료·Git·인증 설정·호스트 연결 프로그램은 제외했다.
- 별도 UI 검증 환경에서 사무실 입장 → 체험 직원 업무 지시 → 회의실 질문 답변 → 대표이사실 보고 검토·승인 → 완료 흐름을 확인했다. 기본 사무실에는 검증용 직원·업무를 추가하지 않았다.
- 문·복도를 통한 모든 방 사이 경로, 연속 방 선택, 키보드 입장·퇴실, 동작 줄이기를 확인했다. Chrome 320·390·768·1366px에서 페이지 가로 넘침 없이 모든 방과 업무 기능에 접근했다.
- 두 검증용 CLI 로그의 연결기 → 개별 세션 API → 브라우저 터미널 전달, 사용자·에이전트 역할, 검색·필터, 마스킹, 갱신 중 초안·스크롤 보존을 확인했다. 연결기를 멈추면 마지막 기록을 유지하면서 단절 상태를 표시했다. 기본 8080에서도 실제 프로젝트의 저장 세션 5개에 대한 제한된 공개 대화 수신을 확인했으며 본문은 검증 문서에 복제하지 않았다.
- Chrome 확장 설치 후 네 AI 서비스의 실제 웹 탭 4개(대화 1개·서비스 화면 3개)를 확인했다. 동일 ChatGPT 대화를 별도 검증 탭으로 열면 탭 수 5개·동일 대화의 탭 수 2개가 되고, 그 검증 탭을 닫으면 4개·1개로 복구됐다. 사용자 기존 탭을 닫거나 메시지를 전송하지 않았다.
- 연결 진단 13개 검증에서 네 공급자 모의 모델 목록, 인증·권한 거절, 요청 제한, 서버 오류, 리디렉션, 형식·응답 크기 제한, 시간 초과, 중복 요청 합치기, 만료와 비밀 값 제외를 확인했다. 실제 8080 화면의 15개 점검 항목과 버튼·확인 시각 갱신을 확인했다. 실제 API 키 네 개는 미설정이므로 실계정 인증 성공은 검증하지 않았다.
- 이 시점의 사무실은 평면도 기반이다. 추가 확정된 다층 입체 구조와 입체 직원 보행은 이후 별도 구현·시각 검증 대상으로 남긴다.

## 환경

- Windows, 로컬 Node.js 26.10.0, Docker Engine 29.6.2, Compose v5.3.1.
- 컨테이너: Node.js 24.14.0, 비루트 사용자(uid 1000), SQLite 영속 볼륨.
- 기본 실행: `docker compose up --build -d`, http://localhost:8080.

## 자동 검증

- `npm test`: 서버 19개와 UI 15개, 합계 34개 통과.
- 서버: 체험 업무 전환, 실행 충돌 방지, 공급자 미지원 처리, 중지·재개, SQLite 재시작 보존, 입력 검증과 정적 파일 제공.
- UI: 상태 집계, 실행 가능 조건, HTML 문자열 처리, 프로그램 링크 제한, 네트워크 실패와 중복 재시도 방지, 브라우저 진입 파일의 구문 검사.
- 후속 추가: 사무실 이름 변경 시 데이터 보존, Codex 프로젝트 필터·부분 JSONL 기록·민감 필드 제외·연결 만료·관찰 프로그램 종료, 폰트 파일과 라이선스, 관찰 상태별 캐릭터 동작과 블로그 링크 검증.
- `docker compose config --quiet`, 이미지 빌드, health check 통과.

## 실제 컨테이너 검증

별도 검증용 Compose 프로젝트에서 직원 등록 → 업무 지시 → 답변 → 승인 대기 → 종료 → 재시작 → 재개 → 승인을 수행했다.

- 재시작 후 직원·업무·답변 보존과 일시 중지 상태 확인.
- 재개 후 이전 승인 대기 단계 복원 확인.
- 이미지에 로컬 참고 자료, Git 데이터와 인증 설정 파일이 포함되지 않음을 확인.
- 검증 전용 컨테이너와 볼륨은 제거했고 기본 로컬 컨테이너는 유지한다.

## 브라우저 검증

웹 담당 세션이 별도 테스트 서버에서 Chrome으로 직원 채용, 업무 지시, 질문 답변, 결과 승인, 일시 중지·재개와 실제 JSON 다운로드를 확인했다. 390px 화면에서도 가로 넘침이 없었고, 외부 공급자의 미지원 모델·추론 설정과 업무 실행이 비활성화됨을 확인했다. 서버 중단 시 연결 끊김 안내와 변경 버튼 비활성화도 확인했다.

브라우저 자동 조작 중 도구 시간 초과가 있었으나 세션별 순차 확인으로 주요 흐름을 검증했다. JSON 다운로드 이벤트 감지는 시간 초과였지만 실제 파일 생성은 확인했다.

최종 통합 후 기본 Docker 주소에서도 로컬 서버 연결 표시, 저장 상태 로드, 사무실 재개와 직원 채용 대화상자 동작을 확인했다. 기본 사무실에는 검증용 직원을 추가하지 않았다.

## 아직 검증하지 않은 영역

신규 AI 세션 실행, Claude·Gemini·Meta 업무 실행 연결, 실제 CLI의 승인·중단·모델 변경, 다른 PC로의 세션 복원, 클라우드 외부 접속은 미구현이며 검증하지 않았다. 별도 원격 Codex 엔드포인트는 인수 전달만 자동 검증했고 실제 원격 연결은 검증하지 않았다.

## Codex 관찰 검증

2026-10-21, 이 저장소에서 동작 중인 Codex 0.162.1의 두 세션을 호스트 연결 프로그램으로 확인했다. 작업 폴더가 다른 세션은 제외했고 출력 스냅샷에는 세션 ID·상태·시각과 작업 폴더명만 포함했다. 사용자 대화·도구 출력·계정 정보는 전달하지 않는다. 관찰은 프로세스 생존 판정이나 세션 제어를 제공하지 않는다.

## 화면 개선 및 Docker 통합 검증

- Chrome에서 한글은 Noto Sans KR, 영문은 JetBrains Mono의 실제 글리프 사용을 확인했다. 폰트는 동일 출처에서 제공되며 외부 CDN 요청은 없다.
- 레드 테마의 등각투영 사무실에서 실제 두 세션의 활동 표시, 캐릭터 동작, 읽기 전용 상세, 움직임 전환과 OS 동작 줄이기를 확인했다.
- 390px 화면의 메뉴 줄바꿈과 사무실 배치를 보정했고 가로 넘침이 없음을 확인했다. 콘솔 오류·경고는 없었다.
- `docker compose up --build -d` 후 기본 8080 컨테이너가 healthy인 상태에서 새 이름·블로그·폰트·실제 세션 상태와 상세 화면을 다시 확인했다.
- `/app/bridge`는 읽기 전용, 업무 DB 볼륨은 읽기·쓰기 가능함을 확인했다. 폰트 HTTP 응답은 올바른 MIME과 하루 캐시를 제공한다.
- 화면의 내부 업무 중지는 외부 CLI 관찰을 중단하지 않는다. 관찰 프로그램은 별도 종료 명령을 제공한다.

## 기존 Codex에 실제 지시 전달

- 2026-10-21, 현재 PC의 Codex CLI 0.163.0에서 공식 `codex queue` 지원을 확인하고 `--allow-commands` 연결 프로그램을 실행했다. 관찰 대상 앱 세션 기록은 0.162.1이다.
- 실제 HTTP API에서 현재 협업 세션 UUID로 지시를 생성하고 pending → accepted/QUEUED 접수를 확인했다. 웹 담당 세션도 브라우저에서 한글 지시를 전송해 공식 큐 접수를 확인했다.
- 이는 기존 세션 큐의 접수 검증이다. 작업 완료·모델 답변 원문·승인 처리의 웹 연동 검증은 아니다.
- 서버 26개 테스트에서 요청 중복, 응답 재조회, 만료·재시작·전송 불명 시 재실행 방지, 지시 원문 제거, 미관찰 세션·교차 출처 차단과 한글·따옴표의 직접 인수 전달을 확인했다.
- 후속 통합 `npm test`: 서버 26개와 UI 22개, 합계 48개 통과. UI는 응답 유실 복구, 같은 ID 재시도, 새로고침 시 ID만 복원, 활동 갱신에도 세션 순서 유지 동작을 검증했다.

## 사무실 배치 개선과 최종 통합

- 팀별 책상·유리 회의실·라운지·커피 구역으로 공간을 구분하고 누적 CSS를 정리했다. 한글·영문 폰트와 레드 테마는 유지했다.
- Chrome 320·390·768·1366px에서 가로 넘침이 없고 버튼·상태·메뉴의 한 줄 표시를 확인했다. 장문 직원명과 업무 설명, 여섯 캐릭터, 모달 입력과 좁은 화면을 함께 확인했다.
- 기본 Docker 8080에서 새 화면·두 실제 세션·사무실 재개를 확인했다. 하이픈으로 시작하는 한글 지시를 화면에서 전송하여 공식 큐 접수까지 확인했다. 원래 Codex의 후속 작업 완료를 의미하지는 않는다.
- 컨테이너 healthy, `/app/bridge` 읽기 전용, `/app/commands` 읽기·쓰기, 브라우저 콘솔 오류·경고 없음. 임시 UI 테스트 직원은 기본 사무실에 추가하지 않았다.

## 공급자 서비스 링크

- 공식 서비스와 설치·인증 문서를 확인하고 ChatGPT·Claude·Gemini·Meta AI 접속 버튼, 공급자 연결 안내 Wiki를 추가했다. 외부 공급자의 실행 가능 상태는 변경하지 않았다.
- `npm test` 49개 통과(서버 26개, UI 23개). 공급자별 고정 주소만 허용하며 임의 주소·다른 공급자 주소·알 수 없는 공급자 ID는 링크로 표시하지 않는다.
- Docker를 다시 빌드하고 Chrome 1920px·320px에서 공급자 카드와 버튼이 넘치지 않는 것을 확인했다. 여덟 링크 모두 새 탭과 `noopener noreferrer`를 사용하며 콘솔 오류·경고는 없다. 컨테이너는 healthy다.

## CLI 추가·종료 감지

- 2026-10-22, Windows의 Codex CLI 0.163.0에서 첫 메시지를 입력하지 않은 새 CLI를 실행하고 실제 프로세스 감지를 확인했다. 별도 검증용 CLI의 `/quit` 정상 종료와 강제 종료가 각각 `running`에서 `exited`로 바뀌었으며 기존 작업 CLI는 계속 실행 중으로 유지됐다.
- 기본 Docker 8080과 최신 호스트 연결 프로그램에서도 확인했다. 빈 CLI 추가 시 `/api/state`와 `/api/discovery`의 실행 수가 4→5, 종료 후 5→4로 바뀌고 종료 이벤트는 한 번만 생성됐다. 해당 빈 CLI는 저장 대화 목록에 추가되지 않았다.
- 관련 자동 검증 14개가 통과했다. PID 재사용, 중복 이벤트 방지, 하루 이상 입력이 없는 실행, 조회 실패·복구, 오래된 스냅샷, 종료 기록 만료, 비공개 필드 제외, HTTP 상태 반영과 인계 제외를 확인했다. 저장 대화 폴더가 아직 없어도 연결 프로그램이 시작되는지 검증했다.
- 감지 범위는 같은 Windows 로그인 세션의 지원 CLI다. 현재 작업 폴더의 저장 대화와 프로세스 목록을 분리하며, 대화 UUID와 프로세스를 추정 연결하지 않는다.
- Claude Code·Gemini CLI의 공식 실행 파일·npm 진입점 구분은 자동 검증했다. 이 PC에는 두 CLI가 설치되어 있지 않아 실제 실행·종료 검증은 수행하지 않았다. 다른 운영체제의 프로세스 감지는 미지원이다.
