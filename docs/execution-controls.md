# Codex 모델·추론 강도와 지시 계약

`localSessions.execution`은 `{ status, updatedAt, models }`다. 모델 항목은 `{ id, name, reasoningEfforts, defaultReasoningEffort, isDefault }`만 포함한다. 호스트는 명령 허용 중 공식 `model/list`를 약 30초마다 읽는다. 90초를 넘은 목록, 20초를 넘은 연결 상태, 명령 비활성 상태에는 선택 실행을 허용하지 않는다. 최대 30개 모델과 모델별 12개 강도로 제한하며 원본 응답·설정·인증·계정 정보는 전달하지 않는다.

세션의 선택적 `model`, `reasoningEffort`는 선택 프로젝트의 마지막 `turn_context`에 있는 공개 식별자다. 실행 기록에서 확인하지 못하면 필드를 생략한다. 현재 실행·차기 기본값이 같다고 추정하지 않는다.

기존 `POST /api/local-sessions/:id/commands`의 `{ id, content }`에 선택적으로 `{ model, reasoningEffort }`를 함께 보낼 수 있다. 모델/강도는 형식과 현재 목록 양쪽에서 검사한다. 둘 중 하나만 있거나 다른 실행 옵션이 있으면 400, 목록이 없거나 지원되지 않는 조합이면 409 `MODEL_UNAVAILABLE`이다. 모델·강도도 중복 검사값에 포함하므로 같은 ID에 설정을 바꾼 요청은 409다. 이미 접수한 동일 요청의 상태는 연결 중단·목록 변경 뒤에도 조회할 수 있다.

호스트는 전달 직전 목록을 다시 확인하고 다음 순서로 실행한다.

1. `thread/settings/update`에 `threadId`, `model`, `effort`만 전달한다.
2. 확인 응답 뒤 `thread/queue/add`에 원래 요청 ID를 `clientUserMessageId`로 전달한다.
3. 설정 미선택은 기존 공식 `codex queue` 경로를 유지한다.

작업 폴더·샌드박스·승인·협업 모드는 변경하지 않는다. 설정 변경 응답 유실이면 지시를 보내지 않으며, 큐 응답 유실이면 접수 여부 불확실로 남기고 자동 재전송하지 않는다. 처리 전 본문 제거와 브리지 재시작 시 재실행 금지 규칙을 유지한다. 설정 변경 도중 명령 허용을 끄면 새 큐 제출을 막는다.

접수 응답은 선택한 `model`, `reasoningEffort`, `settingsApplied`를 포함할 수 있다. 추가 오류 코드는 `MODEL_UNAVAILABLE`, `SETTINGS_REJECTED`, `SETTINGS_UNCERTAIN`이다. 설정 적용과 큐 접수는 원자적이지 않으며 UI에서 별도로 안내한다. 모델 지정 요청의 응답 확인 제한은 최대 70초이며 제한 후 자동 재시도하지 않는다. 본문·접수 파일·관찰 모델 목록은 인계에 포함하지 않는다.

## 검증

- Node 테스트: 모의 WebSocket 서버에서 실제 클라이언트의 초기화·모델별 선택·설정→큐 순서·원래 권한 보존·설정 거절/응답 유실·큐 거절/응답 유실·허용 해제·목록 만료를 확인한다.
- API/브리지 테스트: 모델·강도 검증, 중복 ID 충돌, 같은 설정 재조회, 본문 제거·인계 제외를 확인한다.
- UI 테스트: LAN HTTP의 UUID 생성, 원래 설정을 유지한 명시적 재시도, 지원 목록 변경 시 초안 보존을 확인한다.
- 실제 호스트 Codex 0.163.0에서 읽기 전용 모델 목록 조회를 확인한다. 실계정 작업 생성·설정 변경은 실행하지 않으며 모의 검증과 구분한다.
- 브라우저는 별도 메모리 DB와 가상 접수기를 사용한다. 두 테마·320/390/768/1366/1920px·실제 200% 확대에서 모델 전환, 입력·초점·커서 유지와 접수 표시를 확인한다. 개인 직원·실제 대화를 검증 화면에 복사하지 않는다.

호스트의 `ws` 8.22.0 의존성 설치는 `npm ci`로 재현한다. `codex app-server proxy`는 WebSocket 바이트를 전달하므로 해당 프로토콜로 연결한다. 원격 URL·인증은 호스트 실행 설정에서만 받으며 웹 API로 받지 않는다. Docker 서버와 정적 자산은 이 호스트 의존성을 포함하지 않는다.

### 2026-10-22 배포 확인

- 구현 커밋 `7463779`: 전체 자동 테스트 172개 통과. 라이트·다크 각각 320/390/768/1366/1920px 및 실제 200% 확대, 총 12개 화면 조건에서 가로 넘침 없음·제목 22px·입력 16px·조작 높이 44px 이상을 확인했다.
- 별도 브라우저 검증에서 직원의 명시적 대화 연결, 모델 변경에 따른 강도 갱신, 목록 만료, 서버 끊김·복구, 사무실 중지·재개와 초안·초점·커서 보존을 확인했다. 실제 AI 작업은 생성하지 않았다.
- Docker를 재빌드해 0.0.0.0:8080 바인딩과 healthy 상태를 확인했고 호스트 연결기를 최신 코드로 재실행했다. 네트워크 HTTP에서도 새 화면·대화 선택 목록·안전한 요청 ID 생성이 동작하며 브라우저 오류는 없었다.
- 기존 기능 선택과 사무실 중지 상태를 유지했다. 실제 지시는 사용자가 Codex 대화를 직원에게 연결하고 연결 설정의 지시 전송을 켠 뒤 사무실을 재개하여 보낸다.
