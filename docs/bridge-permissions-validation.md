# 호스트 대화 사본의 Docker 읽기 권한 검증 — 2026-10-22

호스트 연결기가 만든 대화 사본은 기본적으로 디렉터리 0700, 파일 0600이다. 호스트와 Docker 서버의 사용자 ID가 다르면 수집은 성공해도 서버가 사본을 읽지 못할 수 있다.

`--shared-gid`를 명시하면 마스킹한 대화·검색 사본에만 디렉터리 0750, 파일 0640과 지정한 그룹을 적용한다. 원본 공급자 기록·인증 자료·명령 폴더는 변경하지 않는다. 연결 설정은 서버의 실제 그룹 번호를 복사할 실행 명령에 포함하고, 대화 읽기 권한 오류에는 연결기를 다시 실행하는 경로를 안내한다.

## 검증

- 모달·HTTP 수정 커밋 `4e7a66f`에 권한 패치를 통합한 작업 트리에서 `npm test` **192개가 모두 통과**했다. Linux에서 권한 테스트의 건너뜀은 없었다.
- `tests/server/bridge-permissions.test.js`는 기본 비공개 권한, 그룹 값 검증, 기존 사본의 갱신, 반복된 원자적 쓰기, 검색 사본의 그룹 읽기와 수집 해제를 확인한다.
- 별도 비루트 UID 65534와 서버 그룹 1000으로 기본 파일 읽기 거절 → 명시한 그룹의 읽기 성공 → 다른 그룹의 읽기 거절을 확인했다. 사본 재게시와 별도 읽기 프로세스 재실행에서도 같은 결과였다.
- 권한 오류 응답은 원문이나 경로 대신 제한된 원인 코드만 전달한다. 그룹 번호 외의 계정 정보나 비밀 값을 실행 안내에 포함하지 않는다.
- 분리된 검증 환경의 Chromium에서 320px 라이트·다크 화면의 오류 안내와 복사할 실행 명령을 확인했다.

## 실행 환경 반영과 한계

실제 반영 시 연결기의 기존 작업 공간·출력 위치·접속 설정을 보존하고 공유 그룹 옵션만 추가한다. 연결기만 정상 종료·재실행하며 진행 중인 공급자 CLI를 종료하지 않는다. Docker 서버에서 대화 응답 상태와 갱신 시각을 확인하고 원문은 검증 출력에 남기지 않는다.

실제 Windows 실행 검증은 하지 않았다. Windows에서는 기존 접근 방식을 유지하고 POSIX 그룹·권한 변경 함수를 호출하지 않는다. 실환경 재구동과 Wiki 게시 결과는 통합 배포 기록에서 별도로 확인한다.
