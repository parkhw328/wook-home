# 상세창·HTTP 검색 보관 검증 — 2026-10-22

## 수정 범위

CLI 대화창은 설정 링크가 그리드의 대화 공간을 차지했고, 320px 화면에서 본문이 창 아래로 잘렸다. 일반 직원 상세창은 본문과 함께 닫기가 스크롤되었으며, 창별 Escape·바깥 클릭·초점 복귀와 화면 이동 처리가 달랐다. 닫기 이벤트가 늦게 도착하면 다시 연 대화의 읽기 상태를 지울 수 있었다.

공통 `DialogLayer`와 헤더/본문 분리로 CLI·직원 상세·직원 연결·검색 상세창에 동일한 닫기 동작을 적용했다. 한 번에 한 창을 표시하고, 화면 이동 시 닫으며, 본문 스크롤과 독립된 닫기 버튼을 유지한다. 방 아래 업무 패널도 접고 다시 열 수 있다. 저장·지시 요청의 처리는 닫기와 분리하고, 늦은 응답은 사용자의 닫기·대상·경로 선택을 되돌리지 않는다. 체험 업무 초안은 직원별로 보존한다.

원격 HTTP에서는 브라우저의 `randomUUID`와 `subtle`이 없을 수 있었다. UUID는 보안 난수 바이트로 생성하고, 직접 붙여넣기 보관은 서버가 본문 해시를 계산한다. 자동 웹 수집을 켜지 않고 입력한 자료만 보관하며 기존 URL·작성자·길이 검증과 마스킹을 유지한다. 현재 확장의 자동 수집은 localhost/127.0.0.1 범위임을 화면에 표시한다.

## 자동 검증

- Node.js 26.8.1, `npm test`: **189개 통과**.
- 새 회귀 11개: 단일 레이어 전환·빠른 재열기·Escape·바깥 클릭과 드래그·경로 변경, HTTP UUID와 저장소 차단, 직접 보관의 동의 범위·중복 방지·URL/역할/길이 검증·마스킹·출처 검사, 검색 상세의 늦은 응답 취소.
- 직접 보관은 2만 자 한글 입력을 허용하고 범위를 넘는 입력·서비스 첫 화면·외부 주소·시스템 역할을 거절했다. 같은 브라우저/대화/작성자/본문의 반복 전송은 메시지를 늘리지 않았고 자동 수집은 계속 꺼져 있었다.
- `git diff --check` 통과.

## 실제 브라우저 검증

Python Playwright 1.62.0과 Chromium을 사용했다. `tests/browser/layer-preview.mjs`의 메모리 DB·합성 CLI 60개 메시지·보관 메시지로 검증했으며 사용자 대화와 실제 AI 명령은 사용하지 않았다. 재현 명령은 [개발 안내](development.md)의 상세창 검증 절을 따른다.

화면 행렬과 원격 HTTP 흐름의 페이지 JavaScript 오류는 0개였다. 스크린샷과 계산값은 로컬 `artifacts/layer-audit/`에 생성한다. 네이티브 확대의 스크린샷은 CSS 좌표로 잘라내지 않고 Chromium의 실제 뷰포트를 캡처하여 확인했다.

## 검증 경계

실계정 웹 서비스의 현재 페이지 구조·첨부파일 내부·전체 계정 기록 수집은 이번 검증에 포함하지 않았다. 원격 주소에서 확장을 자동 연결하는 기능도 추가하지 않았다. 직접 보관과 기존 자료 검색은 원격 HTTP에서 검증했다. 탭의 미전송 초안은 새로고침 후 복원하지 않으며, 브라우저 저장소가 차단되면 새로고침 뒤 직접 보관의 동일 클라이언트 식별도 유지되지 않는다.

이 기록은 소스와 격리 실행 환경의 검증이다. 실제 Docker 반영과 공개 Wiki 게시 여부는 통합 후의 배포 기록으로 확인한다.
